| Manifest Merge Rehearsal | tools/git/manifest_merge_rehearsal.py | kax-conflict-03. | CI Test List Merge Rehearsal | tools/git/ci_test_list_merge_rehearsal.py | kax-conflict-07. Layouts: `inline` (the CONTROL — allowlist as a line-continuation chain inside .github/workflows/icdev-ci.yml), `external` (moved to args/ci_test_files/core.txt, no merge driver), `external-union` (the shipped shape, `merge=union`). | Gated Test List Resolver | tools/ci/gated_test_list.py | kax-conflict-07. Resolves the CI pytest allowlists in args/ci_test_files/*.txt that used to be inlined in icdev-ci.yml, and re-earns the "gate cannot silently shrink" property outside the YAML: `--check` exits 1 when the list is missing, EMPTY, below its recorded floor, names a path absent from the checkout, or lists a path twice (what a careless union merge leaves behind). `--extract-workflow` parses the inline pytest chains out of an arbitrary workflow file, which is how the before/after "no entry changed" diff was produced. | Changed-Test Isolation Run | tools/ci/isolation_run.py | trust-disc-02. Runs every test file the PR CHANGED in its own pytest process -- the "alone" half of "both alone and in-suite", which this pipeline never had (no test-order randomisation, no isolation run, in icdev-ci.yml, pytest.ini, setup.cfg or pyproject.toml). An order-dependent pass is otherwise invisible: a file is green because of what ran before it and stays green until an unrelated core.txt edit reshuffles the run. Resolves the changed set by diffing the merge base (needs `fetch-depth: 0`), filters through `gated_test_list.in_scope` so it and the census agree on what a test file is, and unions in uncommitted worktree edits so it is useful locally. Only ALLOWLISTED changed files can fail the job -- those are already green in-suite, so a standalone failure is real news; a changed file in no allowlist has never gated a merge and may be red for pre-existing reasons, so it is run and warned about instead. Exit 2 when the changed set cannot be resolved: a step that ran nothing must not read as green. | --run, --list, --base, --timeout, --root, --json, [-- pytest args] | Per-file alone/in-suite report; exit 0 clean, 1 gated failure, 2 unresolvable |
| Ungated Test Drift Reflex | tools/genesis/reflexes/ungated_test_drift.py | Genesis reflex (6h, green tier) that samples the test modules named in the `args/ci_test_backlog.txt` census -- the ones CI never runs -- and reports files that went from PASSING to FAILING. Transitions only: a file already failing is known debt and is not re-reported, and a run against a database with no baseline seeds silently instead of filing a card per file. Cards carry a deterministic id so a re-detection updates rather than duplicates, and a module that could not be run never overwrites a real verdict. Complements `tools/ci/gated_test_list.py --check-coverage`, which stops the census GROWING; this watches the files already in it. | (daemon-loaded via importlib) `run(trigger_data, context)` | `{success, metric_value, details}` -- checked / regressed / seeded counts |
| Red-First Proof Gate | tools/ci/red_first_gate.py | trust-disc-01. ANVIL mandates RED -> GREEN and NOTHING ANYWHERE RECORDED THE RED -- a process instruction whose evidence is never captured is the `|| true` failure of D394 in a second form. For every test file the branch ADDS or MODIFIES, this checks out the merge base into a disposable `verify`-actor worktree, applies ONLY that test file on top, runs it there, and runs it here: it must NOT pass against the pre-change tree and must pass against this one. A changed test that still passes pre-change is either asserting current behaviour rather than required behaviour, or is not discriminating at all. The merge-base pytest output is captured into the JSON proof -- that artifact IS the recorded RED. Shares its decision table with `tools/security/reproduction_validator.py` (`decide_discrimination` + `DiscriminationVocabulary`) so the HTTP-replay gate and this one cannot drift apart on the one question they both ask; "fires" means "the predicate evaluated true" there and "the test FAILED" here. pytest exit 5 (no tests collected) is `no_tests`, never `passed` -- conflating those is the same error as the mandate this replaces. Exit codes: 0 clean, 1 a non-discriminating test, 2 the gate COULD NOT RUN (a gate that cannot run is not a gate that found nothing). Exemptions carry a written reason, never a bare count; a docstring-only edit is `not_applicable` because it adds no assertion. Policy: args/red_first_gate.yaml. | --base, --files, --root, --gate, --json, --out | Per-file discrimination proof + captured merge-base pytest output |
