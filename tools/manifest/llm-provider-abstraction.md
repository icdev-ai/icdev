| Agent Loop Primitive | tools/llm/agent_loop.py | Reusable router-level agent loop (`run_agent_loop`) — automatic LLM re-prompting with native tool use: LLM→tool_calls→execute→tool_result→re-prompt→repeat until done. Tool-handler-agnostic; routes through LLMRouter.invoke using `LLMRequest.tools`/`LLMResponse.tool_calls`/`stop_reason` so it works with any tool-capable provider (Anthropic/OpenAI/Bedrock/Ollama). Raises `AgentLoopUnsupported` for the CLI bridge or `supports_tools=false` models. `DONE` sentinel terminates; `max_iterations` cap; `stop_event` aborts; `on_turn` callback for audit/persist. `initial_messages` seeds a pre-built message history (takes precedence over `user_prompt`/`resume_session_id`). Returns `AgentLoopResult`. Also exposes `run_agent_loop_with_rubric(router, rubric=, **kwargs)` — declares "what done looks like" up front; a separate tool-free grader LLM call judges each completed response against the rubric (`satisfied`/`needs_revision`/`failed`) and, on `needs_revision`, injects feedback and resumes the transcript via `initial_messages` for up to `max_grading_iterations` rounds (config: `args/llm_config.yaml` `agent_loop.rubric`). Returns `RubricLoopResult` (result, satisfied, grades, grading_attempts). | router, system_prompt, user_prompt, tools (OpenAI fn schema), tool_handlers, llm_function, max_iterations, stop_event, on_turn | AgentLoopResult (done, turns, final_content, tool_call_log, messages) |
| Semantic Loop Detector | tools/llm/loop_detector.py | ars-loop-01. Catches an agent that keeps *moving* while going nowhere — re-reading the same file under a different path spelling, re-running a failing command with cosmetic variation. `stall_threshold` only sees NO progress and the duplicate guard only sees byte-identical calls, so both miss this and the run burns to `max_total_tokens`, reporting "task too big" instead of "stuck". `detect_semantic_loop(records, config=)` clusters the last `window` tool calls by similarity of **both** arguments and results (mean of `difflib` ratio and token-set Jaccard over normalised text: case, quotes, path separators, `./` segments, token order — digits deliberately preserved, since `5 failed`→`2 failed` is the progress signal). Flags only when the cluster is ≥`min_cluster_size` calls, over ≥`min_distinct_turns` turns, with ≥`min_distinct_variants` byte-distinct payloads, covering ≥`coverage_ratio` of the window. Wired into `run_agent_loop` as control 6 → `ResultSubtype.error_semantic_loop` + `truncation_reason="semantic_loop"` + `AgentLoopResult.loop_detection`. Config: `args/llm_config.yaml` `agent_loop.loop_detection`; per-call override via `run_agent_loop(loop_detection={...})`. | `records` (`ToolCallRecord(turn, name, arguments, result, is_error)`), optional config overrides | `LoopDetection` (detected, tool_name, cluster_size, window_size, distinct_turns, distinct_variants, mean_similarity, reason) |
| Loop Detector Tuner | tools/llm/loop_detector_tune.py | Replays recorded transcripts (Claude Code `*.jsonl`, or an `AgentLoopResult.tool_call_log` `*.json`) through `detect_semantic_loop` after every tool call, exactly as the live loop evaluates it, and reports which windows would have been flagged. Exists because the failure mode that matters is the false positive: a detector tuned only against synthetic loops has never been shown *not* to kill legitimate iterative work. `--max-flag-rate` turns a pinned corpus into a regression gate. | `--transcripts <file\|dir>`, `--limit`, `--window`, `--threshold`, `--min-cluster`, `--min-turns`, `--coverage`, `--show`, `--max-flag-rate`, `--json` | Flag-rate summary + per-transcript flagged windows (text or JSON) |
| Context Compressor | tools/llm/context_compressor.py | Reversible context compression middleware for AI agent workflows. Reduces token usage 60-95% via SmartCrusher (text), CodeCompressor (code), and CacheAligner (prefix normalization) strategies. Uses the headroom library when installed, with a deterministic built-in fallback. Integrates with LLMRouter as a pre-request middleware and persists compression telemetry to `llm_context_compression_log`. Public API: `ContextCompressor.compress(messages, budget_tokens, content_type, cache_align)` → `CompressedContext`; `compress_messages()` one-shot convenience; `handle_compress_context()` MCP gateway handler. | `messages` (OpenAI format), `budget_tokens` (int), `content_type` (`auto`/`text`/`code`), `cache_align` (bool) | `CompressedContext` (compressed messages + original/compressed tokens + ratio + method + decompression map) |


## Context Budget (2026-07-26)
| Tool | File | Description | Input | Output |
|------|------|-------------|-------|--------|
| Context Budget | tools/llm/context_budget.py | Token accounting + evidence packing against a model's REAL context window. Replaces DIC's fixed `results[:5]` x 1000-char evidence slice, which sent ~1.2k tokens regardless of model. `floor_window_for_function()` takes the MINIMUM across a routing chain (two_tier, RL re-rank and the CLI bridge all reorder it at invoke time). Estimation deliberately over-counts — under-counting overflows a request, over-counting packs one fewer chunk. Public API: `estimate_tokens`, `context_window_for`, `floor_window_for_function`, `available_input_tokens`, `pack_evidence`, `config_gaps`, `routed_models`. | `--report`, `--check-config`, `--json` | JSON `{models, missing_context_window, default_window_tokens}` |
