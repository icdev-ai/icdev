# ACE — Autonomous Collaborative Engine (Co-Worker Canvas)
## CUI // SP-CTI

The ACE Co-Worker Engine is the ICDEV™ canvas for assembling, dispatching, and
monitoring teams of autonomous digital coworkers. It is a core building block of
the NOVA initiative; see `tools/manifest/autonomous-coworker.md` for the
ECHO/SOUL/TRUST/SELA integration.

## Canvas Blueprint

| Tool | File | Purpose |
|------|------|---------|
| ACE Blueprint | `tools/ace/blueprint.py` | Flask Blueprint (`ace_bp` + `ace_api_bp`) that mounts the Co-Worker canvas at `/coworker` and the JSON API at `/api/ace`. Provides pages (active teams, role catalog, instance detail, trust leaderboard), launch/status/messages/artifacts/abort endpoints, profile generation helpers, event-bus feeds, and the `/api/ace/iqe-query` IQE widget route. Uses `get_canvas_connection()` because `ace_*` tables have no `tenant_id`/`classification` columns. |
| ACE Event Bus | `tools/ace/event_bus.py` | Ecosystem-wide event emission for automatic coworker dispatch. Any ICDEV canvas emits a topic/payload event; the dispatcher routes it to roles whose listen topics match. Public API: `emit(topic, payload, source_canvas, source_id)`, `get_pending(limit)`, `mark_processed(event_id)`, `store_result(...)`, `get_recent_results(limit)`, `pending_count()`. |
| FileAccessBroker | `tools/ace/file_access_broker.py` | Scoped filesystem read/write for co-worker agents. Validates paths against `folder_access` list in role YAML (mode `r`/`rw`). Prevents path traversal via `Path.resolve() + relative_to()`. Logs every operation to `ace_audit_log`. CLI: none (library API only). |
| ToolRunner | `tools/ace/tool_runner.py` | Allowlisted ICDEV tool execution via subprocess. Blocks destructive patterns (`--force`, `--drop`, `rm`, `DROP TABLE`). Only `green` trust tier can run autonomously; yellow/red gets HITL gate (`TrustKernelDeniedError`). Captures stdout/stderr and persists artifact. CLI: none (library API only). |
| SkillPromoter | `tools/ace/skill_promoter.py` | SIPA-gated daily genesis reflex. Loads pending `ace_skill_candidates`, runs SIPA Mode B, promotes clean/low_risk to `args/ace/roles/candidates/` for human review. Registered as `ace_skill_promoter` reflex (24h interval). CLI: `python tools/ace/skill_promoter.py --json`. |
| Evidence Report | `tools/ace/evidence_report.py` | ATO evidence chain generator. Walks `ace_audit_log`, `ace_coworkers`, `ace_instances`, `ace_artifacts` for an instance and renders a classification-marked evidence report (SSP / JSON / Markdown formats). Reuses `classification_manager` for banners. CLI: `python tools/ace/evidence_report.py --instance <id> --format ssp`. |
| Canvas Role Gap | `tools/ace/canvas_role_gap.py` | Detects canvases with no representative ACE role. Reads `args/component_registry.yaml` for `canvas`/`child_app` components, checks `args/ace/roles/*.yaml` for `canvas: <key>` field, reports gaps as JSON. CLI: `python tools/ace/canvas_role_gap.py --json`. |
| Profile Generator | `tools/ace/profile_generator.py` | LLM-assisted role YAML generation. `generate_canvas_candidate(canvas_key, display_name, description)` writes a candidate to `args/ace/roles/candidates/` for human review (NOT auto-promoted). `batch_generate_canvas_candidates(gaps)` takes gap-detector output and generates candidates for all. CLI: none (library API; invoked via blueprint `/api/ace/profiles/preview` and `/api/ace/profiles/save`). |
| Agent Tool Registry | `tools/ace/agent_tools.py` | Binds ACE built-ins to OpenAI function-calling tool schemas/handlers for `mode: agent` roles. `AgentToolRegistry(spec, instance_id, stop_event).build(tool_names)` returns `(tools, handlers)`. Handlers wrap `FileAccessBroker` (read_file/write_file/list_files), `ToolRunner` (run_tool, trust-gated via `TrustKernelDeniedError`), and a `done` sentinel handler returning `agent_loop.DONE` (stashes `done_summary`/`done_changed_files`). Also offers `list_skills`/`load_skill` from `tools/agent_runtime/skill_tools.py` (hgx-sess-02, read-only, opt-in per role by name) so a co-worker sees the same `.agents/skills` library a standalone agent does — one implementation backs both surfaces. Unknown tool names skipped. CLI: none (library API). |
| Agent Mode (role) | `args/ace/roles/agent_developer.yaml` | New `mode: agent` role field — co-worker runs `icdev.tools.llm.agent_loop.run_agent_loop` instead of the fixed step list. Declares `agent_tools` (tool names exposed to the LLM) and `max_iterations`. `RoleTemplate` (`tools/ace/role_loader.py`) gains `mode`/`agent_tools`/`max_iterations` fields (default `steps`/`[]`/`12`); legacy roles unchanged. `CoWorkerThread._run_agent_loop` builds the system/user prompts, drives the loop with `on_turn` audit+persist, and falls back to step mode on `AgentLoopUnsupported`. |
| CoWorker Thread | `tools/ace/coworker_thread.py` | Per-coworker execution unit: loads role spec, runs step sequence or agent loop, polls message bus, delegates to HITL gates, persists agent turns to `ace_messages`, writes state/audit/skill-candidate rows. Used by `ACEController` and `ACEEventBus`. |
| Persona Query | `tools/ace/persona_query.py` | `query_persona(role_id, question, context) -> dict`: one-shot, synchronous SME consult — loads the role's SOUL.md identity via `soul_manager.build_identity_preamble()` and makes a single `LLMRouter.invoke("ace_persona_query", ...)` call. Deliberately bypasses `ACEController.launch()`'s async multi-role team machinery. Exposed as the `ace_persona_query` MCP tool (`tools/mcp/tool_registry.py` + `gap_handlers.py::handle_ace_persona_query`); primary caller is cross-repo (e.g. idea_lab's Specialist advisor). |
| Persona Generator | `tools/ace/persona_generator.py` | `get_or_generate_persona(domain_description) -> role_id`: LLM-generates a SOUL.md (Core Values / Working Style / Decision Heuristics / Communication Norms / RULES) for a domain with no existing ACE role, slugs it, writes to `tools/ace/roles/<role_id>/SOUL.md`, and caches the mapping in `tools/ace/roles/_generated_personas.json` so repeat calls for the same normalized domain reuse it instead of regenerating. Auto-generated personas are marked unreviewed. Used by `handle_ace_persona_query` when `role_id` is omitted/unknown but `domain_description` is given. |
| Agent Coordination Bus | `tools/ace/agent_coordination.py` | Shared key-value store for sibling agent loops. Agents assigned the same `coordination_namespace` exchange typed artifacts via `post_result` / `read_result` without direct coupling. Library API. |
| Chat Trigger | `tools/ace/chat_trigger.py` | `detect_ace_trigger(content) -> 'explicit' \| 'implicit' \| None` — detects ACE launch conditions in an incoming chat message so the chat surface can auto-spin a coworker team. Library API. |
| ACE Team Monitor (Reflex) | `tools/ace/genesis_reflex.py` | SUPPORT-tier Genesis reflex. Scans `ace_instances` for stale entries older than `STALE_INSTANCE_HOURS` and remediates them (marks abandoned, releases leases). Registered in the Genesis daemon; `run(context, db_conn)` contract. |
| ACE LLM Step | `tools/ace/llm_step.py` | Runs bare-string role steps via `LLMRouter`. Called by `CoWorkerThread._normalise_step()` when a step is a plain string with no `tool` key; produces a message in `ace_coworker_messages` and returns the LLM output. Library API. |
| Markov Step Sequencer | `tools/ace/markov_sequencer.py` | Learns step-to-step transition probabilities from ACE history. Reads `ace_step_transitions`, builds a Markov transition matrix, and reorders candidate next steps by learned probability. Library API. |
| ACE Message Bus | `tools/ace/message_bus.py` | Routes ACE coworker messages over the agent mailbox. Transport contract: mailbox `message_type` is always `notification` (the mailbox DB CHECK is never modified). Library API. |
| ACE Step Executor | `tools/ace/step_executor.py` | Dynamic tool invocation with trust-kernel gating — resolves and runs a step's tool via `importlib`, applying the same green/yellow/red trust tiers as `ToolRunner`. Library API. |
| Team Assembler | `tools/ace/team_assembler.py` | Converts a `TeamManifest` into a persisted `TeamInstance` (roles, coordination namespace, DB rows). `TeamAssembler(...).assemble()`. Library API. |
| ACE Webhook Delivery | `tools/ace/webhook.py` | POSTs instance payloads to external URLs. Retries up to 3 times on 5xx with exponential backoff (1s, 2s, 4s); logs each attempt to `ace_webhook_log`. Library API. |
| SME Registry | `tools/ace/sme_registry.py` | Runtime generation of subject-matter-expert roles that are BOTH advisory and team-capable. `ensure_sme(domain_description, *, capability_bundle=None, allow_reuse=True) -> SmeResult` normalises the domain to a stable label (reusing `persona_generator._normalize_domain_label`), reuses an existing catalog role when similarity >= `REUSE_THRESHOLD` (0.60), and otherwise generates BOTH a `SOUL.md` persona and an executable `args/ace/roles/<id>.yaml` atomically. Closes the split where `persona_generator` wrote only the advisory half, so a generated SME could advise but never be staffed onto a team. Also `find_existing_role(domain_label) -> (role_id, score)`. The LLM authors identity only; all security fields come from `role_policy`. Library API. |
| ACE Role Policy | `tools/ace/role_policy.py` | Capability policy for LLM-generated roles, backed by the hand-authored `args/ace/sme_capability_bundles.yaml`. `apply_bundle(spec, bundle_name)` overwrites every governed field (`trust_tier`, `mode`, `tool_permissions`, `folder_access`, `icdev_tools`, `max_iterations`) with human-approved values, discarding whatever the model proposed. `validate_generated_role(spec, bundle_name) -> list[str]` is enforced on write AND on load: bundle membership, forbidden path prefixes (`args/ace/roles`, `.claude`, `.git`, `tools`, `icdev`), traversal-normalised scope checks, read-only-scope upgrade attempts, and `icdev_tools` re-derived from ToolRunner's own `_ALLOWED_PREFIXES`/`_BLOCKED_RE`. `assert_valid()` raises `PermissionError`. Library API. |
| ACE Chat Result | `tools/ace/chat_result.py` | Returns a finished co-worker team's work to the conversation that launched it. `deliver(instance_id, *, state="complete") -> bool` reads the launch config, acts only on `trigger_source in (chat, chat_suggestion)`, collects `ace_artifacts` (bounded), synthesizes via the `ace_result_synthesis` logical LLM function, and inserts an assistant/markdown `chat_messages` row carrying a `/coworker/<id>` deep link. Failure and empty-output runs post an error-typed message rather than staying silent. Delivery is IN-PROCESS, not via the webhook: an outbound POST would mean the dashboard calling itself over loopback and breaks in air-gapped deployments. Library API. |
| ACE Team Proposals | `tools/ace/chat_trigger.py` (suggest-then-confirm) | `build_team_proposal(context_id, content, user_id, project_id) -> dict|None` persists an `ace_team_suggestions` row and returns an action_card payload WITHOUT launching; `confirm_proposal(suggestion_id, user_id) -> {ok, instance_id, error}` is the only path that spawns agents from an implicit trigger and is idempotent; plus `decline_proposal`, `get_proposal`, `is_expired`. The explicit `@team` path (`detect_ace_trigger`/`maybe_launch_ace`) is unchanged and still launches immediately. `MAX_CHAT_TEAM=5` caps chat-spawned teams without touching the global `MAX_TEAM_SIZE`. Library API + `/api/ace/suggestions/<id>{,/confirm,/decline}`. |
