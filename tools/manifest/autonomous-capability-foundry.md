# Autonomous Capability Foundry (ACF)

> Shard of `tools/manifest.md`. See index at `tools/manifest.md`.

ACF (`tools/foundry/`, route `/foundry`, project prefix `acf-`, flag
`ICDEV_FOUNDRY_ENABLED`) is a 0→1 product factory: it autonomously invents,
designs, decomposes, and ships brand-new ICDEV capabilities. Distinct from
Oracle/Genesis reflexes (which improve EXISTING tasks incrementally) — ACF
creates net-new products. Loop: harvester → synthesizer → **novelty_gate** →
scorer → deliberator (CoD go/no-go) → spec_generator → task_graph → seeder.

## Autonomous Capability Foundry
| Tool | File | Description | Input | Output |
|------|------|-------------|-------|--------|
| Novelty Gate | tools/foundry/novelty_gate.py | THE Oracle differentiator — dedup a candidate concept vs a capability catalog built from EXISTING assets (canvas_registry + tools/manifest/*.md + goals/manifest.md). `score_novelty(concept)` returns `{novelty_score=1-max_similarity, nearest, is_duplicate, rejected, reject_reason}`; below `config.novelty.min_novelty` → rejected ('duplicate' or 'low_novelty'). Deterministic token cosine+Jaccard blend; optional embedding re-rank (air-gap safe). | --concept-json, --catalog, --json | Novelty verdict JSON |
| Harvester | tools/foundry/harvester.py | Pulls raw signals from EXISTING engine stores (no web re-scan) across 5 sources: innovation (`innovation_signals`+`innovation_trends`), creative (`creative_pain_points`+`creative_feature_gaps`), research (`research_challenges`+`research_dossiers`), genesis (`oracle_predictions` — Oracle lens predictions + Internal Awareness gap nodes), telemetry (read-only `introspective_analyzer` analyses: gate_failures/unused_tools/slow_pipelines/knowledge_gaps — never calls the signal-writing path). `harvest(run_id, *, config, conn)` normalizes each row into the foundry_signals shape `(source_engine, source_ref, theme, raw_score, keywords)` and appends it under run_id (tenant_id/classification stamped). Per-source enable/`max_signals` caps from args/foundry_config.yaml. Cross-source dedup (SHA-256 of normalized theme+keywords) collapses the same capability surfaced by two engines to one row (highest score wins). Best-effort: empty/disabled/unmigrated source → 0 signals, never an error. | --run-id, --json | Normalized signal list + foundry_signals rows |
| Foundry Schema | tools/foundry/db/init_db.py | Idempotent PG-first dual-schema (`_SCHEMA_SQLITE` canonical, `_SCHEMA_PG` via .replace transform) creating the six `foundry_*` platform findings tables (runs/signals/concepts/specs/tasks_emitted/outcomes). All carry tenant_id+classification (RLS-aware get_connection, NOT canvas). CHECK constraints derived from `tools/foundry/constants.py`. `init_db()` degrades gracefully (logs, never raises). | init_db(force) | 6 foundry_* tables |
| Spec Generator | tools/foundry/spec_generator.py | Turns one approved concept into `{spec_md, canvas_contract}`. `generate_spec(concept, *, config, conn, persist)` renders a feature spec (problem / capability / target users / architecture sketch / DB tables / routes / success criteria) from a deterministic template (optional LLM-assist enriches the architecture sketch, never blocks). The canvas_contract `{slug, title, env_flag, tables[], modules[], routes[], iqe_collections[], needs_mcp, needs_reflex}` is derived deterministically (slug→acronym table prefix, mcp/reflex keyword heuristics) and ALWAYS carries ≥1 table + ≥1 route so the task-graph templater can emit a buildable epic. Appends append-only to foundry_specs (tenant/classification stamped). | --concept-json / --concept-id, --no-persist, --json | spec_md + canvas_contract JSON + foundry_specs row |
| Engine | tools/foundry/engine.py | Orchestration engine + CLI for one ACF cycle. `run_cycle(*, dry_run, max_concepts, config, conn)` opens a `foundry_runs` row and drives harvest→synthesize→novelty-gate→score→CoD go/no-go→spec_generator→task_graph→seeder.emit, then finalizes the run with roll-up counts. Each stage is invoked through a signature-aware wrapper so a not-yet-shipped stage module (synthesizer/scorer/deliberator/seeder) degrades to a clean no-op instead of crashing the cycle; the shipped stages (harvester/novelty_gate/spec_generator/task_graph) run for real. Rate limits enforced BEFORE emit (from `args/foundry_config.yaml -> rate_limits`): approved concepts capped at `max_concepts_per_cycle`; if active ACF projects (distinct concept slugs with un-done kanban tasks, via foundry_tasks_emitted provenance) ≥ `max_active_projects`, the cycle skips emit and records `status='rate_limited'`. `--dry-run` runs the full pipeline but the seeder does not write. `status()` returns recent runs + active projects + concept pipeline counts. RLS-aware get_connection, tenant/classification stamped. | --run / --status, --dry-run, --max-concepts, --json | run roll-up JSON / status snapshot JSON + foundry_runs row |
| MCP Gateway (foundry_run / foundry_status) | tools/mcp/gap_handlers.py (`handle_foundry_run`, `handle_foundry_status`) + tools/mcp/tool_registry.py (category `foundry`) | Exposes ACF to the unified MCP gateway. `foundry_run(dry_run=False, max_concepts?)` is a Pattern A (direct-import) wrapper around `engine.run_cycle` — triggers one cycle (rate limits enforced inside the engine); `dry_run=true` runs the full pipeline but seeds no kanban tasks. `foundry_status(limit=10)` wraps `engine.status` — read-only pipeline snapshot. Deterministic, JSON in/out, no shell. Also mirrored in `generate_registry.py:GAP_HANDLER_TOOLS`. | foundry_run: {dry_run, max_concepts}; foundry_status: {limit} | run roll-up JSON / status snapshot JSON |
| Task Graph | tools/foundry/task_graph.py | Turns one `canvas_contract` into the CANONICAL full-canvas epic skeleton (the SIPA epic shape, parameterized). `build_task_graph(concept, canvas_contract)` emits an ordered list of `{id, title, description, task_type, priority, depends_on_task_id}` across epics db (constants→init_db→register→append-only/.env/config) → core (one task per non-owned domain module) → engine (orchestration→CLI) → dash (blueprint→templates+mirror+IQE widget→app.py register/nav/start.md→IQE adapter+map+seed queries — the 8-component gate) → mcp (if needs_mcp) → reflex (if needs_reflex) → doc → vv (CodeLens→Coherence+ruff+pytest→companion sync+health→Playwright E2E). IDs are `{slug}-{epic}-{n:02d}` (n restarts per epic); `depends_on_task_id` is a single-parent linear chain (root=None) where every parent resolves. Every build task embeds the project Guardrails (get_connection/RLS, constants-derived CHECKs, append-only registration, 8-component gate) and carries the `integrity_gate` marker (text + `integrity_gate:True`) so the dispatcher self-vets the generated code via SIPA. | --contract-json, --json | Ordered list[task] |
| Constants | tools/foundry/constants.py | Single source of truth for the enumerated values used in both SQL CHECK constraints (`db/init_db.py`) and Python validation — never hardcode these in code or SQL. `SOURCE_ENGINES` (innovation/creative/research/genesis/telemetry), `RUN_STATUSES` (running/completed/failed/deferred/rate_limited/circuit_open), `CONCEPT_STATUSES` (proposed/scored/approved/rejected), `REJECT_REASONS` (duplicate/low_novelty/low_score/cod_reject/vv_fail), `OUTCOME_VALUES` (shipped/vv_pass/vv_fail/abandoned). Helper `sql_in(column, values)` builds the CHECK predicate so the schema is derived from the constants, not duplicated. | import | enums + `sql_in()` |
| Blueprint (canvas + API) | tools/foundry/blueprint.py | Flask canvas blueprint serving the `/foundry` pages and `/api/foundry` JSON. `create_foundry_blueprint()` returns `None` when `ICDEV_FOUNDRY_ENABLED` is off (canvas dark). Routes: `GET /foundry` (cycle roll-up + concept pipeline board → `foundry/index.html`), `GET /foundry/<concept_id>` (detail: scores + spec + emitted kanban tasks + outcomes → `foundry/detail.html`), `GET /api/foundry/runs|concepts|concept/<id>` (read-only JSON), `POST /api/foundry/run` (trigger one cycle via `engine.run_cycle`; 503 if engine absent), `POST /foundry/api/iqe-query` (plain-English → IQE widget). All reads RLS-aware (`get_connection()` + `g.security_context`). Templates mirrored to `icdev/tools/dashboard/templates/foundry/`. | Flask app registration | Blueprint or None |
| Genesis Reflex (foundry_cycle) | tools/genesis/reflexes/foundry_cycle.py | The continuous-autonomy loop — drives ACF on a 12h cadence so the factory keeps inventing without a human kicking each cycle (the reflex equivalent of `POST /api/foundry/run`). Daemon contract `run(config, trust)` — `config` recognizes `dry_run` / `max_concepts`; the second positional is the TrustKernel, not a DB handle. Clean no-op (`status='skipped'`, `success=True`) when `ICDEV_FOUNDRY_ENABLED` is off OR the engine module is absent, so it never trips the breaker while the canvas is dark / unbuilt. When on, delegates one cycle to `engine.run_cycle` via signature-aware forwarding and maps the roll-up onto reflex keys (`harvested`/`concepts_proposed`/`tasks_emitted`/`metric_value`). Registered in `REFLEX_NAMES` in `tools/genesis/daemon.py`; reads ONLY the `foundry_cycle` block of `args/foundry_config.yaml` (cadence + per-cycle cap + dry_run mirror). The Genesis daemon supplies the OUTER per-reflex circuit breaker (distinct from the engine's V&V breaker). | run(config, trust) / CLI: --dry-run, --max-concepts | daemon result dict |
| Seeder | tools/kanban/seed_foundry.py | One-shot Kanban seeder that registers the ACF build epic (project `acf`, task_prefix `acf-`) via the canonical `task_factory.create_tasks` path — never raw INSERT. Emits the full acf-* task chain (db/core/engine/dash/mcp/reflex/doc/vv epics) with single-parent `depends_on_task_id` links and cross-epic prerequisites named in the description text; IDs follow `acf-<epic>-NN` so `kanban_project_sync.py` auto-populates `args/projects.yaml`. `seed(dry_run)` prints the plan with `--dry-run` and writes to the board otherwise. | --dry-run | acf-* kanban tasks |
| IQE Adapter | tools/iqe/adapters/foundry.py | Importing the module registers four read-only IQE collections over the `foundry_*` platform tables (so the `/foundry` IQE widget and `/ask-icdev` can answer plain-English questions): `foundry.concepts` (synthesized concepts, highest composite first), `foundry.signals` (harvested signals, highest raw_score first), `foundry.runs` (cycle roll-ups, newest first), `foundry.outcomes` (build/ship outcomes LEFT JOINed to concept name). All use RLS-aware `get_connection()`, enforce a 200/500-row cap, and wrap each query in try/except returning `[]` if the schema isn't migrated (widget degrades to empty, never 500s). Seed queries: `context/iqe/queries/foundry/01-05` (approved concepts, rejected-by-reason, shipped/failed outcomes, top signals). | import (auto-register) | 4 collections |
