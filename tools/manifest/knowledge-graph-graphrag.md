## Knowledge Graph & GraphRAG

|------|------|-------------|-------|--------|

| Compliance Graph | tools/knowledge_graph/compliance_graph.py | Compliance crosswalk as knowledge graph — NIST/FedRAMP/CMMC controls as nodes with crosswalk edges | --build, --crosswalk, --coverage, --target, --json | Graph/crosswalk/coverage results |

| Canvas Indexer | tools/knowledge_graph/canvas_indexer.py | Indexes canvas design topologies from sidecar databases into main KG (kg_nodes, kg_edges, kg_graphs); supports all 5 canvases (pdc/bdc/ddc/odc/idc) and both SQLite/PostgreSQL backends | --canvas [pdc|bdc|ddc|odc|idc|all] --json | JSON {indexed, errors, duration_ms} |
| Ontology Federation | tools/ontology/federation.py | Cross-canvas ontology federation — merges domain ontologies into ICDEV Core graph, resolves equivalent classes, adds cross-domain properties, SPARQL-like queries, pre-computes rdfs:subClassOf transitive closure. Integrates with tools/knowledge_graph/federation.py | --build-federation, --query, --list-domains, --list-classes, --integrate-kg, --resolve, --json | JSON federation/query results |

| LLM Relationship/Graph Extractor | tools/knowledge_graph/llm_relationship_extractor.py | LLM entity+relationship extraction for the KG bridge. `extract_relationships_llm(text, entities)` infers edges among already-extracted entities; `extract_graph_llm(text)` extracts BOTH entities and relationships in one call — the fix for the 87% of the DIC corpus (488/559 chunks) where the regex extractor finds zero entities and the "+KG" contributes nothing. Constrained to a relationship vocabulary + entity-set (the model may not invent nodes or labels); each edge carries an evidence snippet (TRUST provenance). `is_valid_relationship()` is the guard (letters/underscore, ≤40) that keeps garbage out of `kg_edges.relationship`. Graceful: returns empty on any LLM failure/air-gap so the ingester falls back to the deterministic verb-map path. Routed via `kg_relationship_extraction` (kimi-cloud chain) in args/llm_config.yaml. | `extract_relationships_llm(text, entities)` / `extract_graph_llm(text)` | `[(src,tgt,rel,evidence)]` / `([(label,type)], [(src,tgt,rel,evidence)])` |
| Community Engine (GraphRAG) | tools/knowledge_graph/community_engine.py | GraphRAG community detection + summarisation for DIC. `build_communities(conn)` clusters each DIC document graph's `kg_edges` with Louvain (networkx, seeded/deterministic; canvas architecture graphs excluded via rag_kg_bridge node source), then `summarise_community()` has the LLM write a theme summary per community (deterministic top-entities fallback on air-gap), stored in `dic_community_summaries` keyed by a content-stable `comm-<graph tag>-<membership hash>` id (idempotent; prefix-delete clears a graph before rebuild). `search_communities(conn, query)` ranks summaries by token overlap for GLOBAL/thematic Q&A — the "what are the main themes across all documents" question flat RAG cannot answer. Routed via `kg_community_summary` (kimi-cloud). Needs a KG with edges (unblocked by the LLM extractor). | `--build` / `--search "<query>"` / `build_communities(conn)` / `search_communities(conn, query)` | JSON `{graphs, communities, skipped_small}` / ranked summary rows |
| Entity Resolution (DIC) | tools/knowledge_graph/entity_resolution.py | Merges co-referent KG nodes so the graph is canonical, not N shadows of each entity. The per-chunk LLM extractor mints a fresh node for "Peering"/"ISP"/etc. in every chunk; `resolve_graph_duplicates(graph_id)` collapses each (normalized-label, entity_type) group within a DIC document graph to one canonical survivor, re-pointing every edge via disambiguator.merge_entities and keeping the rest as aliases. `resolve_dic_entities()` sweeps all rag_kg_bridge graphs (canvas architecture graphs excluded). Conservative: same normalized label AND type only — never collapses "ISP"↔"Internet Service Provider" (needs embeddings/abbrev). A failed merge never aborts the sweep. Run before build_communities (wired into the community_refresh reflex). | `--dry-run` / `resolve_dic_entities()` / `resolve_graph_duplicates(graph_id)` | JSON `{graphs, duplicate_groups, nodes_merged}` |
