| SBOM Generator [CANONICAL] | tools/compliance/sbom_generator.py | CycloneDX SBOM generation (1.4-1.7). The ONLY SBOM producer in the tree — ~25 live call sites plus a BLOCKING bdc_canvas gate. Mirrored at icdev/tools/compliance/sbom_generator.py. No other SBOM package exists. Components come from dependency_resolver; every SBOM carries a coverage statement. Signs via sbom_signer when a key is configured (detached `<sbom>.sig.json` + author_signature/signature_algorithm on sbom_records); unsigned generation is the loud default, ICDEV_SBOM_REQUIRE_SIGNATURE=1 makes it fail closed. | --project, --format, --spec-version, --python-env | SBOM path |
| Dependency Resolver | tools/compliance/dependency_resolver.py | Resolved (transitive) dependency sets per ecosystem — the SBOM 2026 Coverage element. Mirrored at icdev/tools/compliance/dependency_resolver.py. | --project-dir, --python-env, --json | Components + per-ecosystem coverage report |
| SBOM Minimum Elements Validator | tools/compliance/sbom_minimum_elements_validator.py | Scores any CycloneDX (1.x) or SPDX (2.2/2.3 JSON) document against the 2026 Minimum Elements — 17 data fields + 6 applicable practices, each met/partial/gap with a rationale. Grades third-party/vendor SBOMs, not just ICDEV-generated ones. Distinguishes unknown-to-author from withheld-by-author (`UNKNOWN_MARKERS` / `WITHHELD_MARKERS` are the shared vocabulary — import them, don't restate them). Optional `--record` appends to the append-only `sbom_conformance_assessments`. Mirrored at icdev/tools/compliance/. | --sbom, --json, --min-score, --require-conformant, --record, --project-id | Per-element verdicts + weighted score; exit 1 below threshold, 2 unreadable |
| SBOM Evidence Collector | tools/compliance/sbom_evidence.py | The four compliance assessors' shared SBOM eye (sbx-fmt-02). `fedramp_assessor`, `sbd_assessor`, `cssp_assessor` and `ivv_assessor` used to decide an SBOM existed because a filename matched `*sbom*` — an empty file named `sbom.json` satisfied all four. This keeps the discovery globs, then opens each candidate and scores it with `sbom_minimum_elements_validator`. Four verdicts, never a boolean: `absent` / `ungradeable` (empty, not JSON, XML, or a format the validator declines) / `deficient` / `conforming`. Filters signature sidecars, directories and prose out of the glob results; caps reads at `MAX_SBOM_BYTES`; XML is declined with a reason rather than parsed. Carries no threshold — blocking is `sbom_conformance_gate.py` (sbx-gov-01). Library first: import `collect_sbom_evidence`, `has_real_sbom`, `describe`, `detail`, `find_sbom_candidates`, `grade_sbom_file`. Mirrored at icdev/tools/compliance/sbom_evidence.py. | --project-dir, --json | {verdict, candidates, findings, conforming, deficient, ungradeable, best}; exit 0 only when conforming |
| SBOM Signer | tools/compliance/sbom_signer.py | SBOM Author Signature — the 2026 Minimum Elements element. Wraps tools/crypto/attestation_signer + key_manager; signs the canonicalized SBOM and writes a detached `<sbom>.sig.json` beside it. Approved algorithms only (FIPS 186-5 ECDSA P-256/384/521 and Ed25519) — HMAC-SHA256 and an empty signature are refused, because a symmetric MAC is not attributable to an author. Fully offline on both paths: no sigstore/Fulcio/Rekor/OCSP. Verification needs only the SBOM + signature; `--expect-fp` turns integrity into authorship. Called by sbom_generator, which persists the value + algorithm to sbom_records. Mirrored at icdev/tools/compliance/sbom_signer.py. | --sign, --verify, --key-path, --expect-fp, --list-algorithms, --json | Signature block / verification result |
| SBOM Component Producer | tools/compliance/component_producer.py | Component Producer, the 2026 SBOM Minimum Element that REPLACED Supplier Name (sbx-fld-02). Resolves the one organization that creates, defines and identifies each component, offline, from the package's own metadata — PyPI `Author`/`Maintainer`, npm `author`, a Maven POM `<organization>`, a crate's `authors`, a nuspec `<authors>` — falling back to `args/sbom_producer_registry.yaml` to turn a Go module host path or a reverse-DNS Maven groupId into an organization name. NEVER populates the producer from CycloneDX `group`, which is a namespace: `_reject_namespace_echo` drops any candidate that echoes it. A component with no identifiable producer is explicitly marked of unknown provenance with a machine-readable reason, because the standard says silence is not acceptable. Writes `manufacturer` on CycloneDX 1.6+ and `supplier` below it, plus authoritative `icdev:component-producer*` properties on every version. Library first: import `ProducerContext`, `resolve_producer`, `apply_producer_to_cyclonedx`, `producer_properties`, `producer_db_value`, `validate_sbom_producers`. Mirrored at icdev/tools/compliance/component_producer.py. | --purl \| --name/--version [--ecosystem] [--project-dir] [--python-env] \| --validate \<sbom.cdx.json\> \| --registry [--json] | {producer, provenance, source, evidence, reason}; for --validate {valid, component_count, producers_known, producers_unknown, errors[]} and exit 1 on a conformance failure |
