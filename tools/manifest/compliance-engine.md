| SBOM Revision & Frequency | tools/compliance/sbom_revision.py | SBOM 2026 **Frequency** and **Accommodation of Updates** — the two practices, one mechanism (sbx-prc-02). Every generation appends a row linked to its predecessor via `supersedes_sbom_id`; a CORRECTION is a **successor** row, never an edit, so the corrected record keeps describing the document a recipient may already hold. There is deliberately no `superseded` column — `revision_chain` derives the mark at read time from the forward links. `content_digest` digests the document with serialNumber/timestamp/version stripped, which is what distinguishes a substantive revision from a re-issue of identical content; the file hash cannot, because it never matches across two emissions. `evaluate_frequency` answers the per-build question from `source_revision` FIRST and treats `sbom_max_age_days` as the stale-evidence backstop — this is the reconciliation of CLAUDE.md's "regenerated on every build" with the 30-day gate; SBD-21 calls it. Writes `sbom_revised` / `sbom_corrected` audit events. | SBOM Unknown Information | tools/compliance/unknown_information.py | Explicitly Identifying Unknown Information, the 2026 SBOM Minimum Element that REPLACED Known Unknowns (sbx-prc-01). | SBOM Component Licenser | tools/compliance/component_licenser.py | Component License, the 2026 SBOM Minimum Element that is NEW in 2026 (sbx-fld-04). Resolves every component's license into one of four shapes the standard allows and never omits it: an SPDX expression parsed with the ISO/IEC 5962 Annex D grammar and validated **allow-list only** against the vendored SPDX License List, a URL to the full terms, a license name, or an explicit undisclosed marker. Anything not on the list — a misspelling, `Apache License 2.0`, an invented id, an exception used where a license belongs — is carried through as a license *name*, so nothing the recipient cannot resolve is ever presented as resolvable. The proprietary-conditions flag is **tri-state and evidence-driven**: true from npm `UNLICENSED` / `SEE LICENSE IN`, an SPDX `LicenseRef`/`DocumentRef`, the `NONE` keyword or proprietary vocabulary; false means "no conditions the recipient cannot look up", NOT "open source" (BUSL-1.1 is false on purpose); unknown for a bare URL or name, rather than defaulting to false and asserting the absence of conditions nobody checked for. Unknowns and withholdings go through `unknown_information`, never a marker of its own — the local reason travels as the disclosure *detail*. | SBOM Component Hasher | tools/compliance/component_hasher.py | Component Hash Value and Component Hash Algorithm, the two 2026 SBOM Minimum Elements that are NEW in 2026 and were entirely absent (sbx-fld-03). Resolves an ASCII hexadecimal digest of the **executable component artifact** in one of three ways and never omits the fields: recomputed from a local artifact with `hashlib` (preferred — the only path where ICDEV verifies rather than repeats; Maven's local-repository jar is the real case), adopted from the digest the resolved source declared (npm/yarn `integrity` SRI, Cargo.lock `checksum`, NuGet `sha512`/`contentHash`, a Python lock's single `sha256:` file hash), or the explicit unknown marker with a machine-readable reason. Carries the vendored **IANA Hash Function Textual Names** registry and validates allow-list only; separates *registered* from *approved*, so `md5`/`sha-1` parse but are REFUSED rather than published, and `shake128`/`shake256` validate as names but are never emitted (no fixed digest length). NEVER adopts a value that is not a digest of one artifact — `go.sum`'s `h1:` is a SHA-256 over a listing of per-file hashes, and a lock naming several artifacts without saying which was installed is ambiguous — but nothing refused is dropped: it travels on `icdev:component-hash-unadopted` with its reason. Declared digests are length-checked against the algorithm, so a mislabelled digest is refused rather than handed to a recipient as a verification that cannot succeed. Unknowns and withholdings go through `unknown_information`; a withheld hash suppresses `hashes`, the method, the evidence and the unadopted digest. Writes the long-dead `sbom_components.hash_value`/`hash_algorithm` columns. Emission is CycloneDX `hashes[]`, which `spdx_writer` translates into SPDX `checksums`. Library first: import `resolve_hash`, `record_hash_disclosure`, `apply_hash_to_cyclonedx`, `hash_entries`, `hash_properties`, `hash_db_value`, `hash_file`, `normalize_algorithm`, `validate_sbom_hashes`.
