## LLM Providers (Additional)
| Tool | File | Description | Input | Output |
|------|------|-------------|-------|--------|
| Gemini Provider | tools/llm/gemini_provider.py | Google Vertex AI Gemini LLM provider | (library) | GeminiProvider |
| CLI Bridge Activate | tools/llm/cli_bridge/activate.py | Auto-enable Claude CLI provider — prepends `claude-cli` to routing chains when air-gapped or no cloud key; gated by `ICDEV_CLI_BRIDGE` env. Also exposes the context-scoped override (`cli_bridge_override`/`reset_cli_bridge_override`/`apply_cli_bridge_override`) that lets a single request bypass/force the bridge | config dict | rewritten config |
| CLI Bridge Page Toggle | tools/dashboard/api/cli_bridge_api.py | Flask `before_request`/`teardown_request` middleware (`register_cli_bridge`) seeding the router CLI-bridge override from the `icdev_cli_bridge` cookie / `X-ICDEV-CLI-Bridge` header for the whole page, so every canvas AI endpoint honors the per-page toggle even when `ICDEV_CLI_BRIDGE=1`; resets in teardown to prevent leakage | Flask app | (registers middleware) |
| CLI Bridge Job Store | tools/llm/cli_bridge/job_store.py | RLS-aware CRUD over `cli_llm_jobs` for deferred CLI LLM requests: create/claim/complete/fail/get/list + `wait_for_job` (polls to terminal or timeout). Atomic guarded claim; never raises on benign races | (library) | job dict / job_id |
| CLI Bridge Provider | tools/llm/cli_bridge/cli_provider.py | `CLILLMProvider` (ptype=`cli`): `invoke` = `resolve_backend` → `create_job` → dispatch to backend module → `wait_for_job(soft_wait_seconds)`. done→LLMResponse; error→LLMUnavailableError; still running→`CLIJobDeferred(job_id=...)` (subclasses LLMUnavailableError so chat callers go background while others fall back). `resolve_backend` resolves `auto`→subprocess (if headless-capable) else mailbox; honors explicit override + `ICDEV_CLI_BRIDGE_BACKEND`; records the chosen backend on the row | LLMRequest | LLMResponse / raises |
| CLI Bridge Capability | tools/llm/cli_bridge/capability.py | Backend-selection probes: `is_cli_headless_capable()` (CLI binary resolvable on PATH/abs-path, `ICDEV_CLI_HEADLESS` override) drives `auto`→subprocess-else-mailbox; `mailbox_worker_alive()` best-effort heartbeat check (`ICDEV_CLI_MAILBOX_HEARTBEAT`) — advisory only, never gates enqueue. Pure, side-effect-free, never raises | (library) | bool |
| CLI Bridge Subprocess Backend | tools/llm/cli_bridge/subprocess_backend.py | `dispatch(job_id, backend)` runs `claude -p <prompt> --output-format json` in a daemon thread (no hard kill; ceiling `ICDEV_CLI_BRIDGE_MAX_SECONDS`=900), parses result+tokens, then `complete_job`/`fail_job`. Bounded concurrency (`ICDEV_CLI_BRIDGE_MAX_CONCURRENT`=3) + in-flight dedup. Emits `cli_synthesis` SSE progress (queued→running→done) keyed by job_id. Non-blocking; never raises | job_id / job dict | (writes job row) |
| CLI Bridge Manager | tools/llm/cli_bridge_manager.py | Auto-detects whether the `claude` CLI binary is installed and configures `ICDEV_CLI_BRIDGE` in `.env` accordingly. Commands: `--status` (show bridge state + JSON), `--auto-config` (enable if CLI present and no cloud API keys), `--enable` (force-enable), `--disable` (comment-out key in .env). | --status \| --auto-config \| --enable \| --disable \| --json | exit 0/1 + human-readable or JSON output |
| LLM Proxy Keys | tools/llm/proxy_keys.py | Issue/list/show LLM-proxy virtual keys for /gameday & /academy cohorts (lpx-keys-01). Key returned exactly once at creation; only a SHA-256 hash is stored (mirrors api_key_auth). Master/admin key read from `ICDEV_LLM_PROXY_MASTER_KEY`, never logged or returned. Best-effort LiteLLM `/key/generate` sync when the proxy is enabled+reachable, OFF by default. Scopes onto existing tenancy: tenant/team/guild/user. MCP tools: `proxy_key_issue`/`proxy_key_list`/`proxy_key_show` | issue/list/show subcommands + --json | key metadata (+ virtual_key once on issue) |
| LLM Proxy Budgets | tools/llm/proxy_budgets.py | Per-key spend budget accounting + allow/warn/block enforcement (lpx-keys-02). Wires budgets onto existing grouping units via the key's scope (team/guild/user); deny is scoped to a single key/window so one team exhausting its budget never blocks another. Windowed (exercise/day/month/none). Additional layer to gateway.py's per-agent cost cap; orthogonal to rate_gate.py concurrency gate. `check`/`spend`/`record` subcommands | key_id + --projected/--cost | allow\|warn\|block decision / spend summary |
