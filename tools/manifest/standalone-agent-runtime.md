# Standalone Agent Runtime (SAG)

> A persistent, interactive agent process. A thin orchestration shell over
> ICDEV's production agent loop, chat persistence, and provider abstraction —
> it introduces no new LLM execution path or storage. Canonical package:
> `icdev/tools/agent_runtime/` (mirrored to `tools/agent_runtime/`).

| `tools/agent_runtime/dispatch.py` | Turns discovery `ToolSpec` `module`/`handler` coordinates into agent-loop `handler(input, stop) -> str` handlers (sag-reg-02). | `tools/agent_runtime/safety.py` | Command-approval safety layer (sag-safe-01) — the real `SafetyGate` for the reg-02 dispatch seam. Composes the existing `tools.airgap.hook_compat.run_pre_tool_check` (destructive-git + append-only-table hard blocks) with an approval flow: modes `manual` (always prompt), `smart` (cheap-tier LLM risk judgment, heuristic fallback; auto-approve low risk), `off` (`--yolo`, still audited). `ICDEV_SAG_APPROVAL_MODE` sets the default mode. Approver is injectable (`console_approver` default; gateway agent-mode injects a messaging-adapter approver). Every approve/deny is appended to the existing append-only `hook_events` trail via `store_event` (no new table). `build_safety_gate(mode=…, approver=…, router=…)`. `toolsets.build_toolset()` uses it by default; `AgentRuntime.use_toolset(bundles, approval_mode=…, approver=…)` swaps the runtime onto a gated bundle. **ars-appr-01**: `_heuristic_risk` no longer ends in `return "low"` — it defers to `approval_gate.classify()`, so `smart` mode can no longer auto-approve a tool nobody enumerated. |
| `tools/agent_runtime/approval_gate.py` | Reversibility gate for irreversible agent actions (ars-appr-01). Classifies a tool call as `reversible` / `recoverable` / `irreversible` / `unknown` from `args/agent_approval_policy.yaml`, and halts the last two for confirmation. **Fail-closed by construction**: `default_tier: unknown` is in `require_approval_tiers`, so a tool must be *named* to run unattended, and an unreadable/missing policy file makes every tool `unknown` rather than authorising anything. Irreversible content patterns escalate **any** tool (a shell is only as reversible as the string it is handed); downgrade patterns apply **only** to the declared `command_tools`, so incidental argument text cannot make `git_push` look recoverable. Defers to `run_pre_tool_check` hard blocks first (a hard block is not a question). Every approve *and* deny is appended to `agent_approval_log` (migration 342, append-only) with actor + reason, storing argument **key names only** plus a SHA-256 of the input — never argument values, which can carry CUI. `build_approval_hook()` returns a `PreToolUseHook` for `run_agent_loop(approval_gate=…)`; `ICDEV_AGENT_APPROVAL_MODE` = `enforce` (default) \| `dry_run` \| `off`. CLI: `--classify`, `--list-policy`. |

## Genesis reflexes (SAG-owned)

- **`agent_cron_reflex`** (sag-cron-01, 1-min): drains due `agent_cron_jobs`; agent/script exec modes, retry/backoff, delivery; every run logged to append-only `agent_cron_runs`.
- **`sag_skill_curator`** (sag-skl-01, 24h, dry-run default): archives (never deletes) idle, unpinned `icdev-auto-*` skills; pin support. Skill **promotion stays strictly HITL** — this reflex only curates already-promoted skills.

Both are registered in `REFLEX_NAMES` (`tools/genesis/daemon.py`) + `args/genesis_config.yaml` per the genesis-reflex registration gotchas.

## MCP exposure (intentional non-registration)

The SAG runtime is surfaced via the **CLI** (`icdev chat`/`sessions`/`cron`/`profile`, `python -m tools.agent_runtime`) and the **gateway** (agent-mode over the 8-gate security chain) — not as new MCP tools. The local file-write/terminal surface (`mutating_tools.py`) is **deliberately NOT MCP-registered** so it is never exposed to an external agent over MCP; cron/profile/skills-lifecycle are operator-facing management surfaces gated by HITL/allowlist, not agent-callable tools. External-agent MCP access is instead the curated-toolset surface (`sag-mcp-01`, `tools/mcp/unified_server.py --toolset`). No new `security_gates.yaml` entries are required — mutations flow through the existing sag-safe-01 `SafetyGate` + `invoke.py` allowlist. SAG tests are DB-independent (faked persistence), so the SAG tables (`agent_cron_jobs`/`agent_cron_runs`, `sag_profiles`, `sag_skill_registry`, `sag_user_profiles`, `remote_agent_sessions`) self-create via `_ensure_schema()` and are intentionally absent from the conftest `MINIMAL_ICDEV_SCHEMA`.

## Extension seams

- **Slash commands (sag-rt-02):** `AgentRuntime.command_handler` is an injectable
  `(runtime, raw) -> (handled, response, should_exit)` dispatcher. A minimal
  built-in set (`/new`, `/tools`, `/help`, `/exit`) ships here; the full
  data-driven registry plugs in via this seam.
- **Gateway agent-mode (sag-gw-01):** reuses the same runtime + command handler
  behind the Remote Command Gateway's 8-gate security chain.
- **Tool discovery (sag-reg-01):** `discovery.build_registry()` supersedes the
  hardcoded `build_builtin_toolset()` with a registry-driven toolset assembled
  from the MCP registry + built-ins + `@tool`-decorated functions.
- **Toolset bundles + dispatch (sag-reg-02):** `toolsets.build_toolset()` consumes
  `discovery.ToolSpec` `module`/`handler` coordinates via `dispatch.build_handlers()`
  to build agent-loop `handler(input, stop) -> str` callables; bundles defined as
  YAML data in `args/agent_toolsets.yaml`.
- **Safety layer (sag-safe-01):** `safety.build_safety_gate()` is the real gate;
  `toolsets.build_toolset()` installs it by default (fail-closed only if it cannot
  be built). Mutating tools cannot execute without passing `run_pre_tool_check`
  and, per mode, operator approval.
- **Checkpoints (sag-safe-02):** the approval flow is the trigger point — before an
  approved destructive command runs, snapshot affected paths (wires the `/rollback`
  stub in `commands.py`).
- **Gateway agent-mode (sag-gw-01):** inject a messaging-adapter `approver` into
  `build_safety_gate()` so approvals happen via confirmation replies.
