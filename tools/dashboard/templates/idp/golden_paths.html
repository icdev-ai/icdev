Golden paths

A golden path is how a new service starts conformant by construction: icdev scaffold service <key> --path <id> renders it, and the path declares which engineering standards it satisfies, by id and version ({{ view.get('config', {}).get('path', 'args/golden_paths.yaml') }}). The standards that apply to a path are derived from the register: every standard in force that its repo answers to. A path that does not declare one of them is behind, and CI fails. The drift check scaffolds the path into a temporary tree and runs the IDP scorecard and the five-rules audit on the result: a standard checked by a scorecard rule must pass by machine; one checked by a manual evidence step shows needs evidence. Anyone proposes a new version and runs its drift check; a person who did not author it publishes it ({{ templates.publish }}) or later retires it ({{ templates.retire }}). Scores per repo are on the standards scorecards.

Propose a new version

A proposal decides nothing. It records the version at its digest; run its drift check, then a person who did not author it publishes it. The declaration below starts from every standard in force that applies to the path.

Twin

The Developer Portal's governance twin observes the golden paths: a path with no published version, or none drift-checked, is unverified; a path behind the standards in force, a failed or stale drift check, and a version in use only on its bootstrap seed are findings. Each finding carries its thread to the ledger row it rests on. Recorded observations and their replay are on the governance twins page.
