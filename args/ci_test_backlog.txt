#
# Every line is a test module that pytest collects and that CI has NEVER run, so
# it has never gated a merge. Enumerated rather than counted: a bare count can be
# held constant while the set churns (fix one, add one), which would let the gap
# regrow behind a green gate. Identity is what gets tracked.
#
# THIS FILE ONLY SHRINKS. When you make a file pass, append it to
# args/ci_test_files/core.txt and DELETE its line here, in the same PR. Forgetting
# the deletion is not fatal — `--check-coverage` reports a line that is now gated
# as a STALE backlog entry, and `--prune-backlog` removes them in one sweep — but
# the count in args/test_gating_gate.yaml (backlog_max) will not fall until it goes.
#
# NEVER APPEND HERE to silence the gate on a NEW test file. A new test file goes in
# core.txt, green, in the PR that adds it. Appending here pushes the effective
# backlog over backlog_max and the Test job goes red naming this file — which is
# the whole point of the ratchet.
#
# NOT union-merged, unlike args/ci_test_files/*.txt. This file only ever loses
# lines, and union merge resurrects a line deleted on one branch when it collides
# with the other branch's edit — which for a shrink-only file is precisely
# backwards. Two PRs deleting different lines merge cleanly on their own.
