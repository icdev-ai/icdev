# WHY THIS FILE EXISTS. `KANBAN_REQUIRE_ACCEPTANCE_CRITERIA` ships `report`, not `enforce`, and
# this list is why. Arming it would make every module below raise ValueError on its next run --
# and five of them are LIVE reflexes seeding `fix` cards on a 6-hour cadence
# (claim_verifier_reflex, coherence_to_kanban_reflex, qa_agent_reflex, ungated_test_drift,
# route_perf_reflex), so the autonomous loop would stop within hours. That is refusing routine
# work, which CLAUDE.md treats as grounds to stand a check down.
#
# THE PATH TO ARMING IS TO DRAIN THIS FILE. Give each module a real acceptance criterion for the
# cards it seeds -- what would a reader check to know the card was delivered -- and remove its
# line. When the file is empty, flip SEED_DEFAULT_MODE to `enforce` and the gate costs nothing.
#
# IT MAY ONLY SHRINK. A new entry means a new seeder that cannot be judged, which is the defect
# this programme exists to stop. Add the criterion instead.
#
# SELECTION IS CONSERVATIVE: a module is listed only if it calls create_tasks, names a `build`
# or `fix` task_type LITERALLY, and never mentions acceptance_criteria. Modules that build
# their specs dynamically are NOT listed -- they cannot be judged statically, and listing one on
# suspicion would put an undrainable entry in a shrink-only file. They are named at the bottom
# as a comment so the omission is visible rather than silent.
