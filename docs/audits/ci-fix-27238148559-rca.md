## 2. Root cause

Network Canvas DB tables (`topologies`, `nc_projects`, `nc_templates`, `simulation_results`, etc.) do **not** have `tenant_id`/`classification` columns. When the ICDEV storage layer attaches the global Flask `security_context` in a request, the injected RLS predicate references those missing columns and raises `UndefinedColumn` on every query, causing the Network Dashboard to return HTTP 500 under PostgreSQL.

## 3. Fix already landed

The remediation is present in the current `irad/feature` HEAD:

- `tools/network/db/init_db.py` lines 47–50 disable RLS by calling `set_security_context(None)` on the connection returned by `get_connection()`, matching the canonical `get_canvas_connection()` pattern:

```python
# Network canvas tables have no tenant_id/classification RLS columns;
# disable RLS so the predicate doesn't UndefinedColumn / filter rows.
try:
    conn.set_security_context(None)
except Exception:
    pass
```

Because the fix is already in HEAD, this CI failure is a **stale-target** run (the branch/ commit that triggered it did not yet contain the fix). No additional code change is required.
