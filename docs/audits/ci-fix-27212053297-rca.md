## 3. Why was /network/ 500'ing on the original branch?

The fix to the network index route that landed on `irad/feature` in
`f87f9b4d7` (`fix(network): replace SQLite JSON functions with Python-side
parsing for PG primary`) plus the upstream hardening in `2e9c8513c`
(`fix(network): project pages work on shared PG (missing/colliding tables)`)
both wrap the `simulation_results` queries in a `try/except`:

```python
# tools/network/blueprint.py — current HEAD
try:
    sims = [...SELECT...simulation_results...fetchall()]
    total_sims = conn.execute("SELECT COUNT(*) FROM simulation_results").fetchone()[0]
except Exception:
    try: conn.rollback()
    except Exception: pass
    sims = []
    total_sims = 0
```

Those commits exist on `irad/feature` HEAD but were **NOT yet on the
`kanban/ci-fix-27221875236` worktree** when CI ran run 27212053297. The
fix is the 2e9c8513c back-port (commit 3ac745986 — `fix(ci): degrade
network /network/ index on missing simulation_results (CI 27212053297)`).

## 6. Pattern

Three prior CI runs hit the same stale-target pattern and were closed
no-op. The recurring signature: a `canvases_extended.spec.ts` test
flags `/network/` as a 500 because the kanban worktree branch is behind
