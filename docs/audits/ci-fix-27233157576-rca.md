## 3. Why was /network/ 500'ing on the original branch?

The fix that landed on `irad/feature` in `f87f9b4d7` (`fix(network): replace
SQLite JSON functions with Python-side parsing for PG primary`) plus the
upstream hardening in `2e9c8513c` (`fix(network): project pages work on
shared PG (missing/colliding tables)`) both wrap the `simulation_results`
queries in a `try/except` so a missing/incompatible table degrades to empty
lists rather than 500'ing the index:

```python
# tools/network/blueprint.py — current HEAD (5fb2641ea)
try:
    sims = [...SELECT...simulation_results...fetchall()]
    total_sims = conn.execute("SELECT COUNT(*) FROM simulation_results").fetchone()[0]
except Exception:
    try: conn.rollback()
    except Exception: pass
    sims = []
    total_sims = 0
```

Those commits exist on `irad/feature` HEAD but were **NOT yet on the
`kanban/ci-fix-27233157576` worktree** when CI ran run 27233157576. The fix
that unblocked the very first such failure was back-ported in
`3ac745986` (`fix(ci): degrade network /network/ index on missing
simulation_results (CI 27212053297)`).
