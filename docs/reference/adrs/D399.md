**ONE emulator switch, and the contradiction case is refused rather than guessed.** ICDEV carried TWO unrelated switches for the same emulator and neither knew the other existed: `databridge/feature_flags.py::localstack()` read `LOCALSTACK_ENABLED` and told the operator to run a compose profile `docker-compose.yml` had never declared, while `studio/executors/_base.py::detect_mode()` returned a mode on the bare PRESENCE of `LOCALSTACK_ENDPOINT` — and *that* is the switch under `terraform apply`. So the flag could be off while the executor ran against an emulator, or on while nothing was reachable. `tools/cloud/emulator.py` (flx-seam-01) is now the one answer and both existing switches delegate to it; `LOCALSTACK_ENABLED/_ENDPOINT/_REGION` stay readable as **deprecated aliases**, so an operator's existing configuration is not silently ignored. Three decisions inside the seam are load-bearing. (1) **An endpoint declared while the switch is OFF degrades to `dry_run`** — plan only. Falling through to `aws` on ambient credentials would send an apply written for a local emulator at a REAL account; neither reading is defensible, so nothing is applied. (2) **Credentials are always `test`/`test`, never the ambient AWS pair** — these values reach `docker run -e` and a Terraform provider block, the emulator accepts any non-empty pair, so honouring a real `AWS_ACCESS_KEY_ID` buys nothing and hands live GovCloud keys to a container talking to localhost. (3) **`docker_backed()` is TRI-STATE.** Measured on this host 2026-09-04, Docker Desktop 28.5.1 was RUNNING while `os.path.exists(r"\.\pipe\docker_engine")` returned False — a plain existence check reports a definite absence for a working daemon. Windows-with-no-`DOCKER_HOST` is `None` (cannot tell) and PERMITS the call; only a PROVEN absence refuses, because refusing on an unproven absence fabricates a refusal — the mirror image of fabricating an empty list.
