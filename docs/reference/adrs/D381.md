**Federation is EXTEND, not duplicate.** Air-gap validation (fed-01) is a config-driven shared rule module (`args/twin_airgap_rules.yaml`) emitting `deployment_blocker` violations, wired into NDC/PDC/IDC adapters; deny-by-match (guards the "query-as-compliance false-confidence" risk). Target presets (fed-02) reuse the existing `context/cloud/csp_service_registry.json` (not a new catalog) + the fed-01 air-gap rules; PUBLIC-DATA-ONLY (customer catalogs via `ICDEV_CSP_CATALOG_PATH`) with a 180-day staleness guard. Corrected the docs' claim that `cross_csp.py`/`validate_region` cross-CSP simulation exists — `cross_csp.py` is absent; `validate_region` lives in `tools/cloud/region_validator.py`.
