**The research loop was scoring an IDENTITY baseline, its master switch was read by nothing, and the fabricated `0.0` was deleting the loop's own audit record — so every unmutated run is now `unmeasurable`, and real mutation waits behind a manual gate.** `args/autoresearch_config.yaml: enabled: false` had shipped since the engine landed and the nightly `experiment` reflex ran the loop regardless; `autoresearch_enabled()` is now the ONE reading of it, with the env override outranking the config **in both directions** (it is the per-host knob for an opt-in loop that ships off) and an unreadable config **fail-closed** under `basis: config_unreadable`, so "declared off" and "could not tell" stay apart. Worse than the switch: `run_loop` evaluated a domain, created an experiment, ran it, evaluated **again with nothing changed**, and decided keep/discard on that delta — which is why every result carried `placeholder_metrics: True` and a note saying so, and why a nightly reflex reported 73 runs and 73 successes at `last_metric_value` 0.0. Any placeholder domain now makes the **whole** run `unmeasurable` (metric None, `total_kept`/`total_discarded`/`acceptance_rate` None, **no GKP export**), and a placeholder domain's keep count rides as `kept_unmeasured` and never `kept`, because a total summed across a measured and an unmeasured domain is not a total. **The 0.0 was self-erasing**: `base.run_reflex` suppresses the audit row when `metric_value == 0 and not details.get("tasks")`, so those 73 runs wrote 73 `reflex.started` rows and **not one** `reflex.completed`; `None == 0` is False, so the refusal is now recorded, and two daemon seams that coerced it back to a number (a `TypeError` on `evaluate_metric(cfg, None)` — an honest "could not measure" would have been scored a FAILURE and tripped the breaker, hiding the gap behind a disabled reflex — and a `float(metric or 0.0)` that staged a `pending_review` GKP for a run that did not run) are fixed. The Foundry is the same shape one module over: **4 of its 8 stage modules do not exist**, including the SEEDER, its only writer of a kanban row, so `tasks_emitted: 0` was never the gate verdict it reads as; `run_cycle` now distinguishes `stages_missing` / `stages_present` (which modules IMPORT) from `stages_ran` (which were INVOKED — a present stage still does not run under the circuit breaker), reports `unmeasurable` with the absent stages NAMED, and keeps `success: True`, because an unbuilt stage is a gap and not a failing cycle. A standing claim (`experiment_loop_measures_a_change`) guards it live with two derivations sharing no column, no reduction and no author: reported = the loop's own keep count, derived = DISTINCT experiment ids whose `pre_metric != post_metric`; verdict `agrees` at 0 and 0 over 9 rows, every one of which has `pre_metric == post_metric` **exactly**. **Real mutation is gated, not shipped**: `xrv-lab-02` sits behind `xrv-gate-00`, a manual sentinel whose risk line says why — opening it spends real tokens nightly on autonomous code mutation, and that is an operator's decision and not a scheduler's. Until it opens, the honest report is `unmeasurable`, which is the point: a loop that reports a measurement it did not make is worse than one that reports nothing. `experiment_programs` is created in both schemas and read and written by nothing, so it is registered as a substrate and probes `empty` — named rather than dropped, because deleting a table two schemas declare is its own decision. Tasks: xrv-lab-01..02, xrv-gate-00.
