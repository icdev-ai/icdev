**A Claude Code dispatch's cost exists only in its transcript, an ABSENT price is never `$0.00`, and the two MCP usage counts are never merged.** None of the four token ledgers sees a `claude_cli` session: the adapter bypasses `router.invoke`, so every one of those calls carried no cost row, and `agent_token_usage.task_id` held **ZERO** rows on the live board although `_parse_cli_json` had been parsing `total_cost_usd` per dispatch all along and writing it to a task log nothing read back. Three decisions make the repair honest rather than merely present. (1) **The CLI's own `total_cost_usd` is recorded AS REPORTED and never re-priced** — `args/llm_config.yaml` prices no Claude Code model, so re-pricing would substitute our table's silence for the vendor's measurement; an unknown or `0.0/0.0` model is `unpriced` with `cost_usd` **None**, and a mixed bucket is `partial`, a stated lower bound. The direction of the error is what makes this load-bearing: `record_task_cost` originally fell back to `0.0` for an envelope carrying no cost field, so an absent price summed as a zero and **understated the bill in the direction that makes work look cheap**. `row_is_unpriced` now names that class and the count is carried APART from every outcome verdict, because a dispatch that reported no dollars still shipped or was still abandoned — folding it into `unmeasurable` would make the verdict answer a question about the price instead of about the outcome. (2) **"Did the spend ship" is a CLOSED verdict set** — `shipped | reverted | abandoned | in_flight | unmeasurable` — joined through `landed_check` (task -> main, per repo) and `pr_linker`, where an unreadable ref, an unreadable board, and a forge `MERGED` beside a default branch naming no commit (a **disagreement**, never a pick between two) are all `unmeasurable` and never fold. (3) **The two MCP usage figures measure different CALLERS and are printed side by side.** `studio_mcp_dispatch_audit` has exactly two writers, both Studio-internal, and nothing under `tools/mcp/` writes a dispatch row, so **every MCP call made from a Claude Code session is invisible to `capability_consumption --class mcp_dispatch_tool`**: measured on this host over 30 days, the transcripts say 3 of 472 registry tools were reached and the Studio audit says 1. Neither is a correction of the other and neither alone answers "is this tool used", so no probe and no budget was changed (`mcp_dispatch_tool: 467` is untouched) and the server-side audit write — a new writer to an append-only table — is its own card. Measured while building it: attributing a transcript tool name against `TOOL_REGISTRY` **bare** credited **Playwright's** 50 clicks and 176 navigations to ICDEV, because the registry and the Playwright MCP server both declare `browser_click`/`browser_navigate`/`browser_type`; attribution is now server-qualified from the checkout's own `.mcp.json`. The panel that renders all of this is a **section on the existing `/cache-savings` page** and computes no cost of its own (one `survey_by_verdict` call, forge deliberately not consulted, an AST test refusing a private cursor), because a panel with its own query is how a surface comes to disagree with the CLI about a number neither of them changed.
