**REA is adopted through two EXISTING seams with no new subsystem, Ghidra is the only default engine, and every rail is enforced by ICDEV because REA's own `SECURITY.md` says "This is not a sandbox".** rea-spike-01 measured `rea-agents@6.4.0` on Windows 11 and Linux: GO for PE (both OSes), ELF (Linux only — Windows Ghidra P0 is PE-only), .NET CIL, JS bundles (`detail: summary` + exported bundle; `complete` overflowed the 10,484,736 B MCP budget on a 30 KB bundle) and HAR (export only, with `sensitive_values` — a body CSRF token survived); NO-GO for WASM. Payloads were byte-identical across cold runs and OSes, and measured egress was only REA's loopback/AF_UNIX engine bridge. The same spike found that ICDEV's own `ghidra_headless.py` returned **no result on any OS** on Ghidra 12 (a Jython post-script against a Jython stub, with the abort invisible in the report) — an optional backend that had never once run — which rea-eng-02 fixed by moving to PyGhidra. Decisions: (1) REA enters as an `args/external_mcp_servers.yaml` entry — `enabled: false`, exact npm pin checked against the installed package, a read-only allowlist DERIVED from REA's declared tool `effects` rather than hand-kept, `single_user_only`, and an authorized-target gate that hashes every artifact argument against a grant — and as analyzer-contract observable types; (2) the engine is chosen by `args/re_engines.yaml` by license CLASS: Ghidra (Apache-2.0, `oss_redistributable`) is default and installable; Hopper (`byo_single_user`) and IDA (`oem_required_for_shared`; IDA Free is non-commercial only) are bring-your-own, declared by the user in a user-owned file, never installed or downloaded, refused on SaaS/shared deployments, and REA's `auto` provider choice is never used; (3) RE runs only on a single operator's own machine, with target sha256 + authorization basis (`owned | licensed | customer-authorized`) in provenance and a run without one refused; (4) REA and the engine run inside `SandboxExecutor` (plus the omx-guard-05 L3 write sandbox where available); (5) process capture is opt-in per run (`allow_execute is True`) and browser capture is not wired; (6) decompiled output is `basis: decompiled`, observed behaviour `basis: observed`, neither presented as recovered source; (7) an unmeasured list is `None`, never REA's `[]`; (8) CI replays recorded responses through a stub MCP server and never needs Node or Ghidra. Deliberately NOT adopted: `rea setup` (it rewrites harness configs ICDEV's companion sync owns), Hopper/IDA defaults, adb device actions, EVM analysis (no consumer — adopting it would ship a declared-but-unconsumed capability), and any non-opt-in capture.
