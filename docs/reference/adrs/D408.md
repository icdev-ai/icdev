**Two files agreeing with each other is not currency, and a freshness check NEVER pulls, never edits a pin, and never reads "I could not reach the registry" as "the pin is fine".** The floci pins are cryptographically verifiable — `parse_pin` refuses a tag and `verify_bundle` re-hashes every OCI blob against its filename — and that machinery answers "does this bundle contain exactly what we pinned". It cannot answer, and nothing else asked, **"is what we pinned still the current release"**: the `floci/floci:2.0.1` pin's only ongoing assertion was a test that two files agree, and two files can agree perfectly about a version that shipped a year ago. AGREEMENT IS NOT CURRENCY. `args/pinned_artifacts.yaml` enumerates 16 artifacts and is a **declaration, never a second copy of a pin** — each entry names the file the pin actually lives in and the survey reads it through `image_vendor.parse_pin`, so there is no second parser to drift from, and a `pin_source` disagreeing with the manifest is `unmeasurable` rather than resolved in favour of one side. Four decisions. (1) **Three states, never merged: `current | behind` (the newer release NAMED) `| unmeasurable`** — and an air-gapped deployment, the one `tools/airgap` exists to serve, reports every artifact `unmeasurable` and **never `current`**, because a freshness check that read an unreachable registry as a clean pin hands exactly the disconnected operator a fabricated clean bill. `current_pct` is None, never 100.0, over an empty denominator, while a measured 0.0 stays a real red bar. (2) **Two bases for `behind`, and which one decided is recorded**: `version_tag` where the pinned tag carries an ordering (same SUFFIX and component count only, so `16.4-alpine` supersedes `16.3-alpine` and `16.4` does not, because a different suffix is a different image line), and `digest` where it does not — `redpanda:latest` and `k3s:latest` are pinned by a MUTABLE tag, so "newer" for them is knowable only as the tag having MOVED off the recorded digest, and `digest_drift` is None and never False when it could not be compared. (3) **It never acts on a pin.** `subprocess`, `os` and `shutil` are unimportable in both modules, the one HTTP door is GET/HEAD only, nothing opens a pin file for writing, and the reflex files ONE card per `behind` artifact through `task_factory.create_tasks` into `suggested` rather than moving the pin — moving a digest pin is a supply-chain act that belongs in a reviewed diff, which is the whole reason the pins are digests. Asserted against the AST and not the source text, because both modules explain in prose that they never touch `subprocess`, so a grep would flag their own explanation of themselves. (4) **ONE code path for every registry**: the host comes from the ref and the bearer token from the registry's own 401 challenge, so Docker Hub, `public.ecr.aws` and `ghcr.io` need no per-registry table, and the declared upstream is cross-checked against the host the ref implies so a label cannot disagree with the fetch. First live survey, 2026-09-12: **16 declared, 10 current, 6 behind, 0 unmeasurable** — postgres `16.3-alpine -> 18.6-alpine`, mysql `8.0.36 -> 26.7.0`, valkey `8 -> 9`, opensearch `2.19.5 -> 3.8.0`, amazonlinux `2023 -> 2027`, registry `2 -> 3` — with **three also carrying digest drift**, meaning an air-gap bundle re-cut from the tag today would not contain what the pin says. Both `:latest` pins measured UNMOVED since 2026-09-05, the positive control for the digest lane. Task: xrv-pin-01.
