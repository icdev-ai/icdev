**Binary analysis is TWO TIERS with TWO declarations, an optional backend that reports its own absence is the whole point, and a version TOKEN is not a version.** ICDEV had zero binary analysis — no PE/ELF parser, no strings, no entropy, no decompiler — while `slsa_verify` and `attestation_verify` verified metadata about an artifact **without ever opening it**, which is precisely what "the binary does not match the SBOM" is about. The socket already existed (`args/analyzer_contract.yaml` + `tools/analyzers/sandbox.py`), so this is two analyzer entries and no dispatcher change. **The tiers are separate modules and separate declarations on purpose:** `binary_triage` is pure Python and its guarantee is that it **executes nothing**, asserted from its AST; `ghidra_headless` spawns a JVM. One entry covering both would silently widen the guarantee that makes `binary_triage`'s sandbox posture (Gap 71) arguable while leaving the wording unchanged. Ghidra needs a JDK 21+ and a ~400 MB install, so it is deliberately **not** in `requirements.txt` and the one thing it may never do is a successful-looking empty report: five statuses (`ok | truncated | unavailable | timeout | error`), and `functions`/`imports`/`strings` are **None — never `[]`** whenever nothing looked, with the reason named, because an `[]` there reads as "Ghidra looked at this binary and found no functions" — a claim about the ARTIFACT from a run that never opened it. A MEASURED `[]` survives as `[]`, and both directions are asserted. Two implementation facts are load-bearing rather than incidental: **the two timeouts are not the same timeout** (`-analysisTimeoutPerFile` is set BELOW the wall budget, so an over-running analysis still runs the postScript and yields a PARTIAL export this module can label `truncated`, instead of a killed process with no export to label at all), and **the process TREE is killed, not the process** — `analyzeHeadless` is a `.bat`/`sh` wrapping a JVM, so `proc.kill()` reaps the wrapper and leaves the JVM holding the pipes `communicate()` is blocked on. On the consumer side, **a binary's strings are a HINT and are labelled one**: `evidence: binary_strings`, `confidence: unasserted` (there is no second value), the RAW string carried so a reader can check, and no purl invented. **THE TOKEN IS NOT THE VERSION** — `_VERSION_TOKEN` ends at a word boundary, so the seam's hint for `OpenSSL 1.1.1k` is `1.1`, a *wrong* version rather than a vague one, and a CVE lookup against it answers about a release the artifact does not contain; the token is extended over the version characters following it in the same string and **both** values ride on the component with `version_basis` naming the rule. The residual (`v1.1.1k` yields no hint at all) is reported and pinned by a test rather than repaired here, because a second regex in the SBOM seam would make the SBOM and `binary_triage --json` disagree about one artifact. And corroboration is **reported beside the signature verdict and never folded into it**: `attach()` returns a new mapping with every existing key unchanged and REFUSES to overwrite, asserted as equality over the WHOLE result on both verifiers — so a triage that cannot load `pefile` can never downgrade a sound verification, and an adversary who can make the triage unmeasurable cannot move the verdict. The SBOM axis is deliberately asymmetric: only a version CONTRADICTION on a name both sides carry reaches `disagrees`, because static linking leaves no trace, a version string can name a protocol or somebody else's requirement, and the generator's honest `unknown` marker must never become a finding.
