**The scanners existed; nobody had pointed them at the files that configure the agents — and a brand-new check over an undrained surface registers at `warn`, with the false positives fixed BEFORE arming rather than excused after.** `prompt_injection_detector.scan_project`, `secret_detector.scan` and `mcp_scanner.scan_mcp_servers` had all shipped, and `SKIP_DIRS` never excluded `.claude/`, `.agents/` or `.cursor/` — `scan_project` would have walked them the first time anybody asked, and nobody asked. Pointing them there is `warn`-level in `coherence_checker` (capped in code and asserted by test), full-tier only, re-added to the fast tier exactly when a diff touches the config surface, because a hard refusal on day one over a 227-file surface nobody has drained is how a check earns itself a `|| true`. **Arming it meant fixing the scanner first, and the finding was large:** `role_hijack_jailbreak` spelled its pattern without word boundaries, so every occurrence of `dan` INSIDE a longer word was a CRITICAL jailbreak finding — **10,019 matches across 18,730 files, of which 9,929 (99.10%) were `guidance`, `accordance`, `dangerous`, `redundancy`, `pydantic`**, and 67 of 67 criticals on the config surface itself. Adding `\b` is a strict narrowing (it cannot create a match) and the existing DAN fixture still fires, so the fix is provably not a weakening. Two further defects are handled at the CALLER rather than at the scanner, on purpose: `secret_detector`'s `--exclude-files` regex is **unanchored**, so it silently drops every path containing `build` or `dist` (proven as a controlled pair — the same file with the same planted token yields 1 finding under `.agents/skills/x/` and **0** under `.agents/skills/icdev-build/`), and anchoring it widens what ~20 consumers including the `domain_leak_gate` CI gate report, which owes its own fire-rate survey; so `config-secrets` runs **both scanner arms** and unions the findings, making its live `pass` a measured zero over all 227 files. And `scan_mcp_servers` returns `passed: True` for a config it never found — a clean bill of health for nothing — so the check treats an `error` key as **unmeasurable** and an absent file as **absent**, never as a pass. The same discipline governs the routing epic: `args/tool_index.yaml` is the ONE declared list of the ~36 external binaries this platform shells to, `which(name)` REFUSES an undeclared name (an index that silently answers for anything can never grow), **`present` requires the binary to ANSWER its `version_cmd`** because a `present` verdict that never ran the binary is a claim about a file NAME — measured, two binaries called `helm` are on PATH and only running them settles which one you got — and `unmeasurable` is its own state that never folds into either other; the 195-case corpus over the **four** deliberately separate routers adds **no fifth router** and carries its four discovered defects as `xfail(strict)` cases, red while the defect stands and red the moment it is fixed and the declaration goes stale; and the 69-site pin census is a shrink-only ratchet grandfathered BY NAME, `warn` in coherence, with `requirements.txt`'s 45 ranges **surveyed and not gated** because the install-time pin for a deployment is the vendored wheel set. In every case the predicate is RE-DERIVED each run rather than kept as an exemption list — 21 of 29 compose images are built by this repository and a registry digest has no meaning for them, so the predicate excludes them and no reviewer has to check a list.
