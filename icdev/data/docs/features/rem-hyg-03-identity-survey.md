# rem-hyg-03 — What would the identity check have refused on the real board?

**Status:** measured, report-only. Arming is rem-hyg-04.
**Measured:** 2026-08-16, live PostgreSQL board, 3,243 rows / 163 registered cards.
**Tool:** `python -m tools.kanban.identity_survey --json`
**Regenerate:** the numbers below are a snapshot; re-run the tool rather than citing this file as current.

## Why this exists

`tools/kanban/task_identity.py` (rem-hyg-02) is wired REPORT-ONLY into
`task_factory.create_tasks`. CLAUDE.md forbids arming it without measuring it
first, and the rule was learned expensively: over 96,818 real tool calls, eight
of the twelve PreToolUse checks were refusing routine work — 4.86% of all calls
— and the check that motivated that survey had shipped as a hard block a task
earlier with its fire rate never once observed, because `|| true` was discarding
everything it returned.

**A check that is nominally enforcing but never measured is UNMEASURED, not
proven.** This is that measurement.

## The narrowing is the finding

789 of the 1,127 `no_card` rows are **opaque machine ids** — they were never
card work and were never meant to be counted by a card:

| prefix | rows | generated by |
|---|---:|---|
| `task-<hex>` | 408 | the dashboard's own create-task API (`tools/dashboard/api/kanban.py:63`), `tools/awareness/suggested_card_writer.py:96`, `tools/chat/requirement_intake_hook.py:177` — all `f"task-{uuid4().hex[:10]}"` |
| `mc-reflex-<hex>` | 291 | the migration-canvas reflex |
| `diag-<hex>` | 60 | diagnostics |
| `cpmp-<hex>` | 22 | |
| `chore-…-<hex>`, `pmo-…` | 8 | |

**Refusing these would be refusing routine work** — the identical defect the
PreToolUse survey found. Exempting them:

| population | lifetime | last 90d | last 30d | last 7d |
|---|---:|---:|---:|---:|
| refuse every unclaimed id | 35.43% | 35.71% | 38.46% | 21.69% |
| **exempt opaque machine ids** | **11.10%** | **11.29%** | **16.33%** | **4.23%** |

`classify_shape` is a **named heuristic over id text**. It never decides whether
an id is claimed — that stays `resolve`'s job alone. `-d<N>` decomposition
suffixes are stripped before classifying, so `mvs-audit-03-d1` counts as card
work while `task-fd99a9c8ae-d5` does not; without that, 40 real card rows read
as machine noise.

## Recommendations for rem-hyg-04

1. **Do not arm on `no_card` alone.** At 35.43% it would refuse roughly one seed
   in three, and 69% of those refusals would be machine ids the check has no
   business judging.
2. **Exempt opaque ids explicitly**, not incidentally. 11.10% lifetime / 4.23%
   over the last 7 days is the rate to design against — still far above the
   1.63% the narrowed PreToolUse checks carry, so a refusal should probably
   start on `no_epic` (22 rows, one card) and treat `no_card` as advisory.
3. **The seam does not cover the population.** 95 modules `INSERT INTO
   kanban_tasks` directly and never reach `create_tasks`, including the writers
   behind most of the opaque rows. Arming at `create_tasks` cannot see them —
   and must not be credited with catching them either.
4. **`dispatch_source` cannot settle origin.** It is rewritten at dispatch, so it
   cannot distinguish "a reflex created this" from "the scheduler dispatched
   it". The survey classifies by id shape and says so rather than leaning on a
   column that would look authoritative and be wrong.

## Two zeroes that are never a clean bill of health

Both report `measured: false` and neither is ever rendered as 0% — that would be
the `|| true` failure in report form.

- **`no_registry`** — an unreadable `args/projects.yaml`. Every id would resolve
  to `no_card`: 3,000 fabricated findings rather than a measurement.
- **`empty_board`** — the worktree trap. A worktree has no `.env`, so
  `get_connection()` reads a throwaway SQLite database that has never held a
  task. A 0% rate over 0 rows would read as "safe to arm". Point at the real
  board with `--env-file` and check `board.backend` in the output.
