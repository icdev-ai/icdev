# BDC cATO Twin (Boundary Design Canvas) — CUI // SP-CTI

> Shard of `tools/manifest.md`. See index at `tools/manifest.md`.
>
> Continuous Authority to Operate (cATO) digital twin for the Boundary Design
> Canvas (`bdc`, mounted at `/boundary`). Freezes cross-framework control state
> into append-only snapshots, exposes an IQE query surface, runs a continuous
> Genesis reflex, scores cATO readiness, and exports OSCAL evidence.
>
> **This shard was reconciled against shipped code (task `bdr-hyg-2`).** Several
> modules named in the original brief were never shipped — see
> [Removed / phantom references](#removed--phantom-references-do-not-cite). The
> boundary-level subpackage view lives in
> [`tools/manifest/ato-boundary-impact.md`](ato-boundary-impact.md); the ISA
> lifecycle two-store distinction is documented there too.

## BDC cATO Twin — IQE Integration
- **Canvas adapter:** `tools/iqe/adapters/bdc.py` (NOT `iqe/adapters/boundary.py`). Registers five collections on the module-level IQE Executor: `bdc.designs` (`boundary_designs`), `bdc.assessments` (`bd_assessments`), `bdc.isas` (`bd_isa_tracker`), `bdc.alerts` (`bd_alerts`), `bdc.ai_decisions`.
- **Twin adapter (reflex/CLI surface):** `tools/iqe/adapters/compliance.py` registers `compliance.twin_snapshots` / `.twin_violations` / `.twin_runs` over `compliance_twin_*` and exposes the validated `run_query(iqe_string, conn=None, project_id=None)`. Since bdt-iqe-1 the reflex and `cato_twin/cli.py` drive IQE through this (maintained parser/executor + fail-closed field whitelist + SQL-layer project scoping) — **the Phase-1 regex engine `cato_twin/query_engine.py` was deleted.** Behaviour is proven by `tests/test_bdt_iqe_migration.py`.
- **Seed queries:** `context/iqe/queries/boundary/*.iqe` (FedRAMP Moderate `frm-*` + FedRAMP High `frh-*`, plus AI-decision queries) are file-existence-checked by `tests/test_cato_twin.py::TestIqeSeedQueries`; the reflex's live seed queries are built in `cato_twin.py::_build_seed_queries`.

## Known gaps / follow-up
1. **~~Migrate the reflex off the Phase-1 regex query engine.~~ RESOLVED (bdt-iqe-1).** `tools/genesis/reflexes/cato_twin.py` and `cato_twin/cli.py` now drive IQE through `tools/iqe/adapters/compliance.py` — the maintained parser/executor plus `compliance.twin_snapshots`/`.twin_violations`/`.twin_runs` collections and the validated `run_query`. The regex→SQL Phase-1 engine `cato_twin/query_engine.py` (and its `icdev/` mirror) was **deleted**. The hardened engine's three safety properties carried over: field whitelisting is enforced in the adapter's collection definitions (unknown token → `ValueError`, since the IQE executor otherwise resolves unmapped attrs to `None` silently), malformed syntax fails closed (`IQESyntaxError`), and project scoping is parameterised at the adapter SQL layer. Seed queries were rewritten into the IQE grammar (`== null`, `startswith`). Proven by `tests/test_bdt_iqe_migration.py` (replaces the retired `tests/test_bdc_query_engine_hardening.py`).
2. **~~Reflex writes 0 snapshots — assessor schema misalignment.~~ RESOLVED (bdt-sch-1).** The reflex previously populated 0 rows because `_pull_framework_controls` expected per-control `score` / `evidence_ref` / `assessed_at` columns the assessor tables never exposed (and `cssp_*` / `cmmc_*` key by `requirement_id` / `practice_id`, not `control_id`), and it probed table existence via `sqlite_master` (absent on PG). bdt-sch-1 rewrote the reads to the **actual** schemas — no migration, no new tables — normalizing each assessor's native status vocabulary to OSCAL status with an honestly-derived score (absent evidence stays `None`; no fabricated scores) and mapping `evidence_path`→`evidence_ref`. Design note: no `requirement_id`/`practice_id`→NIST `control_id` crosswalk is applied because `crosswalk_engine` only offers forward NIST→framework mapping over a small curated set — reverse-mapping would drop the majority of real assessor rows (reintroducing empty snapshots). The native per-framework identifier is used as `control_id`, which preserves all real evidence. Proven end-to-end by `tests/test_bdt_twin_evidence.py`.
3. **`cato_monitor` reflex references a missing `controls` table (pre-existing).** `tools/genesis/reflexes/cato_monitor.py` runs the `context/iqe/queries/compliance/*.iqe` seed set, some of which target a `controls` table that does not exist in the schema. Pre-existing gap, unrelated to the twin writer; noted here for cATO-monitoring completeness.
