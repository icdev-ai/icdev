| Supervisor Status | tools/genesis/supervisor_status.py | Is the launcher supervisor up, and what is it supervising? | Deployment Freshness | tools/genesis/deployment_freshness.py | autonomy-dep-03: can this deployment still UPDATE ITSELF, and if not why? Measured 2026-08-21 the live checkout was 22 commits behind origin/main and had stopped updating: 170 files incoming, 11 locally modified, EXACTLY ONE overlap — `args/projects.yaml`. `code_reload.pull_if_safe` refused ("local changes would be lost"), correctly, and NOTHING READ THE REFUSAL. It never cleared because that file is auto-managed by kanban_project_sync.py, which rewrites it in the working tree, while every card registration edits it upstream — so a correct transient refusal became a permanent freeze. The cost was invisible: autonomy-id-01 recorded nothing even after its migration applied, because the RUNNING code had no boot_identity call, and code_staleness could not report that because it needs an identity row only current code writes. Every board, PR and CI signal stayed green. ASKS `pull_if_safe(dry_run=True)` rather than re-deriving the refusal ladder — a dry run performs no merge and does NOT consume the pull throttle, so watching cannot starve the updater. FOUR STATES: current / updatable (behind but the guard would pull — a normal window between cycles, not a finding) / blocked (behind AND refusing — THE finding, carrying the reason and the offending files BY NAME) / unmeasurable. An unmeasurable distance is never a freeze alarm: this module shipped that bug, reporting BLOCKED whenever a ref was unreachable, and a regression test proves the fix. Report only, and must stay so — force-pulling trades a stalled update for silent data loss on a shared checkout. | `--root PATH` / `--ref REF` / `--json` / `--gate` | `{state, behind_by, reason, conflicts[], root, ref}` ; exit 1 blocked with --gate, 2 unmeasurable |
