| PR Linker | tools/kanban/pr_linker.py | Reconciles `kanban_tasks.executor_url` against open GitHub PRs — the link `pr_watcher` needs to see a task's PR at all. Only `kanban.py::_push_branch_and_open_pr` ever writes that column, and only for an un-suffixed `kanban/<id>` branch with a local ref, so PRs opened by retry dispatches (`kanban/<id>-r2`, `-land`) stayed invisible permanently (10 green PRs stranded, 2026-08-02). | Re-Verifier | tools/kanban/reverify.py | Recomputes a task's verification from **durable remote git refs** and APPENDS a `kanban_verifications` row. Exists because `pr_watcher._enforced_done_ok` reads only the latest row and nothing but a dispatch writes one, so one bad verdict blocks auto-merge until re-dispatch — which opens a second PR. The bad verdicts come from `kanban.py::_git_worktree_has_real_changes` reading the process-local `_worktrees` / `_dispatch_main_heads` dicts: after a daemon restart all three of its checks skip and it reports "No git commits found on task branch" for a branch full of work. This module reads `git log <base>..origin/<branch>` only, so the answer is process-independent. Leaves `review_passed` NULL (= "not judged, allowed"); it verifies work EXISTS, it does not judge conformance. Also invoked by `pr_watcher._maybe_reverify` when the enforced done-gate holds (config `reverify_on_hold`, cap `reverify_max_attempts_per_task`); it REFUSES to refresh a `review_passed=0` conformance failure or to invent a first verdict for a never-judged task (`reverify_when_missing`, off by default) — either would launder the gate rather than refresh it. | `<task_id>`, `--base`, `--dry-run`, `--no-fetch`, `--json` | `{result, reason, branch, files_changed, commits, written}`; exit 0=passed / 1=failed / 2=no such task |
| Rebase Recovery | tools/kanban/rebase_recovery.py | Rebases a DIRTY kanban PR branch onto its base so a stale branch is not treated as a human problem (kax-conflict-01). A branch that has merely drifted behind main reports `mergeable: CONFLICTING`, which `pr_watcher` classifies as a resume class — so the PR burns all 5 LLM resumes on a conflict `git rebase origin/main` would have cleared, then escalates to a permanent human queue (measured 2026-08-07: 2 of 5 open kanban PRs DIRTY; `xbm-wake-01` parked 95.7h). Four safety properties: `branch_is_task_owned()` permits ONLY `kanban/<task-id>` or its `-rN` retry sibling (whole-string, not prefix — `kanban/foo-2` is a different task); the rebase runs in a throwaway DETACHED worktree under the system temp dir, never the task worktree or the shared checkout; a rebase with real conflicts is `--abort`ed and pushes nothing; the push is `--force-with-lease` pinned to the sha observed before rebasing. A rebase that replays to zero commits is reported, not pushed (it would empty the PR). Called from `pr_watcher._maybe_rebase` on MERGE_CONFLICT before any resume is spent (config `auto_rebase_on_conflict`, cap `max_rebase_attempts_per_task`); attempts are audited as `pr_watcher.rebase` / `.rebase_failed` so they are a SEPARATE ledger from `pr_watcher.resume` and never consume the resume budget. | `--task <id>`, `--branch`, `--base`, `--repo-root`, `--dry-run`, `--json` | `{attempted, pushed, conflict, reason, branch, base, commits_ahead, old_sha, new_sha}` |
| Idle Advisor | tools/kanban/idle_advisor.py | Explains WHY dispatch produced nothing, and recommends what a human should do (kpr-idle-01). `diagnose()` classifies the idle state as one of `paused` / `wedged` / `review_bound` / `decision_bound` / `chain_bound` / `drained` — six situations the old `idle (no due tasks)` heartbeat rendered identical. For `decision_bound` it ranks the held manual gates by work that would actually become dispatchable, priority mix, and a penalty for tasks whose titles self-declare BLOCKED/DECLINED (dispatching those burns a session). **Read-only by design — it never releases a gate or moves a task**; a gate is a human's "not yet", and an advisor that opened gates to stay busy would trade intent for throughput. **A gate is only justified by a stated risk** (kpr-idle-02): `gates.declared_risk()` reads a `RISK:` line from the gate's description, and a gate that states none outranks every justified gate for release no matter how much work it holds — procedure ("do not move without a decision") is not a risk and cannot be reviewed. Publishes its own `blind_spots`. Wired into the scheduler heartbeat, which now logs the reason instead of a bare `idle`. | `--json` / `diagnose(conn)` | reason + detail + ranked candidates + recommendation |
