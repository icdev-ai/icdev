Keyed on the inventory, so the 5 tags predating the benchmark map report `declared_verdict: None` instead of being dropped. No DB (xbm-cmp-01-d2) | --project &lt;id&gt;, --subsystem &lt;tag&gt;, --all, --validate, --json | Comparison map per subsystem + unmapped_projects + integrity report |
| Benchmark Comparator | tools/innovation/benchmark_compare.py | The verdict engine over d1's measurements and d2's join: `ahead` / `parity` / `gap` / `no_adaptation_needed`, plus a separate `position` (ahead/parity/behind/unknown) so "nothing to adapt" never erases "ICDEV leads". The external half is declared (promoter config + benchmark map); the local half is re-measured every run and overrules it in BOTH directions — a declared gap whose `closes_when` is satisfied is reported retired, a declared lead below the module floor becomes a gap. A finding with no measurable closing condition stays open and says so in `measurement_limits`; an unreachable DB, or one holding none of the subsystem's tables, is `not_assessed` and never `unfed` (xbm-cmp-01-d3) | --subsystem &lt;tag&gt;, --project &lt;id&gt;, --all, --verdict &lt;v&gt;, --json | Verdict + position + basis + outstanding + measurement_limits per subsystem |
| Benchmark Report | tools/innovation/benchmark_report.py | The comparison chain as a document: d1's measurements, d2's join and d3's verdicts rendered to `docs/research/external-benchmark-map.generated.md` with the same structure as the hand-written map — summary table, the ten benchmarked sections in order, the unbenchmarked five kept separate, where ICDEV leads, and one index of everything outstanding. Writes BESIDE `docs/research/external-benchmark-map.md`, never over it: the map is what `benchmark_compare` cites as the origin of every declared reading, and its external narrative lives in no config. Offline by default — module counts are globs and reproduce anywhere, row counts do not, so the checked-in file is byte-identical on any machine and `--check` is a usable CI gate. Offline nothing retires a finding, so the conservative reading is what gets committed; `--live` opens the DB, re-checks every `closes_when` and will say a finding is retired, but refuses to write the checked-in artifact Exact module counts are deliberately NOT written into the committed artifact (kax-conflict-02): they are globs over the tree, so every branch that added a module rewrote the same two lines to a different value and the document conflicted with itself — three of six blocked PRs on 2026-08-08 were held up by this file alone. What is committed is the classification against the module floor (`built`/`thin`/`absent`), so adding a module produces a byte-identical document and `check_report` can go back to comparing exactly; crossing the floor still fails the gate. `--json` and `--live` still carry the integers. (xbm-cmp-01-d4) | --write, --check, --live, --out &lt;path&gt;, --json | Markdown report; --check exits 1 with a unified diff on drift |


## DIC Integration (Epic D — dic-syn-ri)

`stage_discover()` in `innovation_manager.py` accepts an optional `dic_collection_id` parameter.
When provided, it calls `tools/research/source_scanners/dic_scanner.scan_dic_collection()` and
includes the result as a `dic_collection` sub_result — treating DIC RAG chunks as pre-synthesized
signals alongside web scanner output.

```python
from tools.innovation.innovation_manager import stage_discover
result = stage_discover(dic_collection_id="my-collection")
# result["sub_results"]["dic_collection"] = {collection_id, signals: N}
```
