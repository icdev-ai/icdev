## Reproduce-or-Drop for Dynamic Findings (oss-poc-01)
| Tool | File | Description | Input | Output |
|------|------|-------------|-------|--------|
| Reproduction Validator | tools/security/reproduction_validator.py | Reproduce-or-drop rule for DYNAMIC findings (concept adapted from STRIX, clean-room). A finding asserted about a *running* system must carry a stored, replayable reproduction — an HTTP request/response sequence or an agent action trace; otherwise it is `unconfirmed`, is never promoted to a finding, and **never blocks a gate**. `replay()` executes the reproduction and evaluates a *vulnerability predicate* (`status_in`, `body_contains`, `body_not_contains`, `body_regex`, `header_equals`, `all_of`) against the final step. `verify_discrimination()` is the real bar: the same reproduction must fire against the vulnerable target and stop firing once the fix is applied — a predicate that fires against both is reported as a tautology. `validate_predicate()` statically rejects trivially-true predicates (over-broad status lists, empty substrings, regexes matching the empty string, bare negatives). `make_reproduction_grader()` supplies a pluggable code grader to `run_agent_loop_with_rubric`, so an agent claiming a finding is graded on whether its PoC fires rather than on whether its prose convinces. STATIC findings (bandit/CVSS/STIG) are out of scope and pass through untouched. Targets are default-deny allowlisted (loopback only by default); response bodies are never retained — only status, length and sha256. | `--validate <repro.json>`, `--replay <repro.json> [--target URL] --json`, `--enforce <findings.json> --gate --json` | `{total, confirmed, unconfirmed, remediated, blocking, gate_pass, verdicts[]}` |
| Reproduction Policy | args/reproduction_policy.yaml | Thresholds for the rule: `target_allowlist` (default-deny replay scope lock, override via `ICDEV_REPRO_TARGET_ALLOWLIST`), `replay.{timeout_seconds, max_steps, max_body_bytes, allow_redirects}`, `predicate.max_status_codes`, `gate.{blocking_severities, block_on_unconfirmed}`. Flipping `block_on_unconfirmed` to true re-admits unreproduced findings as gate blocks and defeats the module — it exists so that doing so is a visible configuration act. | YAML config | Policy |

Storage: `dynamic_findings` (MUTABLE — status transitions unconfirmed → confirmed → remediated) and `finding_replay_attempts` (APPEND-ONLY, NIST AU — one row per replay ever; in `APPEND_ONLY_TABLES`).
