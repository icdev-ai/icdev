Data discovery export to ICDEV[OS]

What the Data Design Canvas found in a source goes to ICDEV[OS] as one {{ schema }} bundle per declared source ({{ view.get('config', {}).get('path', 'args/data_discovery_export.yaml') }}), against the ICDEV[OS] contract {{ contract }}. Profile the source on Explore first. The bundle carries metadata only, never a datum: each table's row count and each column's type, null and distinct counts; the PII columns the scanner flagged, by the pattern names it matched, never a value; the rule-based anomalies with a fixed description (a model's findings are never exported); the design's quality rules and their latest results (a rule that never ran is not run, never a pass); and the catalogue entries that cover the source. Anyone prepares it, and a person who did not prepare it publishes it ({{ template }}), bound to its digest. ICDEV[OS] marks it by its own config, never by what it claims.

Discovery bundle

Preparing records the source's bundle, as built now, at its digest. It decides nothing. A person who did not prepare it then publishes it to ICDEV[OS] or refuses it, with a reason. Only a published bundle leaves.

Twin

The data discovery twin observes the export ledger: a source with no published bundle is unverified, a published bundle carrying a failing quality rule or one that never ran is a finding, and so is one waiting too long for a person. Each finding carries its thread to the ledger row it rests on. Recorded observations and their replay are on the governance twins page.
