1. Introduction The Indian Health Service (IHS) is responsible for implementing and administering an information security program to protect the agency’s information resources. The procedures in this document are designed to protect IHS technology resources and data by mitigating information security threats, improving incident response, and reducing interference among systems.
Wireless network devices offer a simple, convenient, and inexpensive way to extend network accessibility by reducing the requirements of physical infrastructure. Wireless networking eliminates wired connections on portable devices and makes it possible for laptop and handheld users to travel beyond traditional network boundaries (for example, between buildings) without losing network connectivity. However, in addition to the risks associated with any wired network, wireless technology introduces several unique vulnerabilities. Because wireless signals are radio transmissions, the proliferation of wireless appliances at IHS can lead to increased radio frequency interference (RFI) among medical devices. Furthermore, the signals can be intercepted by other radio receiving devices, including those outside the intended service area. If data transmissions are inadequately encrypted, the intercepted data can be read and understood in a matter of seconds. That means any data transmission sent through the wireless network is at risk, including patient data, user names and passwords, financial data, and other sensitive information. Advances in wireless signaling technology may increase transmission distances, further exacerbating the problem of unauthorized reception. Because wireless transmissions can circumvent traditional perimeter firewalls, existing protections established to prevent unauthorized access are ineffective. Websites that identify open access points (“hot spots”) that malicious users can use to access a network are becoming more common. If the IHS wireless network is improperly implemented, it can enable an unauthenticated user to get an IHS Internet Protocol (IP) address with all the benefits of an authenticated network user. Using one of these trusted IP addresses, a malicious user could attack IHS or any outside network that is connected to IHS.
This SOP establishes the procedure for the secure deployment and use of wireless network technology.
1.1 Purpose and Scope This IHS Standard Operating Procedure (SOP) establishes wireless network security standards and procedures for IHS, compliant with all applicable federal laws and regulations. This procedure is, in large part, based on the National Institute of Standards and Technology (NIST) Special Publication (SP) 800-153, Guidelines for Securing Wireless Local Area Networks (WLANs). 2. Sta ndards for Wireless Network Security All IHS federal employees, contractors, and third-party organizations must adhere to the following requirements and recommendations when they use wireless local area networks (WLANs) on any IHS IT system. 2.1 Requirements

These standards outline appropriate use of the IEEE 802.11 WLANs for IHS. The requirements are based on the IEEE 802.11 family of standards and do not incorporate any proprietary vendor security controls. • WLAN products must comply with IEEE 802.11-2007. • If Simple Network Management Protocol (SNMP) is turned on for management purposes, change SNMP community strings from their manufacturer default to unique and difficult-to-guess strings. • WLANs that are not configured for open/public access must implement IEEE. • Implement 802.1X access control to reduce the risk of access from unauthorized WLAN devices, and provide authentication using a Federal Information Processing Standards (FIPS)-140-validated and Wi-Fi Protected Access 2 (WPA2)-certified Extensible Authentication Protocol (EAP) to verify authorized WLAN devices and/or users. • Encryption for data that traverses a WLAN must use Advanced Encryption Standard (AES) algorithms that are validated under the National Institute of Standards and Technology (NIST) Cryptographic Module Validation Program 1 as meeting requirements of FIPS 140-2, at a minimum Overall Level 1. • WLAN products must be Wi-Fi Alliance, WPA2- certified. • WLAN traffic must be logically segmented from wired network traffic by use of a Virtual Local Area Network (VLAN), when possible. 2.2 Recommendations

The following recommendations will further enhance the security of a wireless network. Where feasible, consider adopting these recommendations in addition to the requirements listed above. • Register the static IP addresses for wireless access points in the Domain Name System (DNS), and use IHS naming conventions. • Use MAC-based authentication by allowing only registered MAC addresses to have access to the AP. It is possible to spoof MAC addresses, but MAC-based authentication provides another layer to the security of an otherwise insecure data transfer medium. • Use multiple levels of authentication and security. Recommendations include using Remote Authentication Dial-In User Service (RADIUS) authentication or public key infrastructure (PKI). • Ensure the wireless device satisfies any existing RFI standards. • Use an encryption protocol between any two wireless devices. At a minimum, the wireless access point must require WPA2 or connect through the IHS-managed VPN concentrator. All encryption modules must be certified under FIPS 140-2. 1 The Cryptographic Module Validation Program is a joint effort between NIST and the Communications Security Establishment Canada, that validates cryptographic modules to FIPS. • Avoid broadcasting to areas not intended for service. Locate APs centrally within the intended area of service, and avoid placing APs near windows or against the outside walls of buildings. • Designated personnel should scan for unauthorized wireless APs (WAPs) annually or when major changes are made. If a rogue WAP is found, the local ISSO must be notified to investigate. (CAUTION: If a scan is conducted in a hospital, the scanner could find devices that appear to be wireless access points but are actually medical devices. Automatically disconnecting such a device is dangerous and may lead to malfunction of medical devices.) • Designated personnel should check annually to ensure that the organization’s WLAN client devices and APs have configurations that are at all times compliant with this SOP. • Disable broadcasting the Extended Service Set Identification/Service Set Identification (ESSID/SSID). • Change all default ESSID/SSIDs from their default vendor settings to unique names. The ESSID/SSID can be accessed from within wireless products’ web- based or Windows-based configuration utilities. Common examples of predefined ESSID/SSIDs are simple names like "wireless," "netgear," "linksys," or "default." An ESSID/SSID can be changed at any time, as long as the change is also made on all wireless clients. The following are best practices:  Don't use information such as name, address, organization, or other types of personal information as part of the ESSID/SSID.  Don't use any of your Windows or Internet website passwords.  Don't tempt would-be intruders by using tantalizing network names like "HEALTHCARE-BOX" or "TOP-SECRET."  Do pick an ESSID/SSID that contains both letters and numbers.  Do choose a name as long or nearly as long as the maximum length allowed.  Do consider changing your ESSID/SSID every few months.

3. Guidelines for Implementing Wireless Networks at IHS Follow these guidelines when implementing or using wireless networks. • To enable wireless access for a user, the user’s supervisor must request the access through the Information Technology Access Control (ITAC) system. • Local IT staff will configure the client access securely, including encryption and layered authentication. • Local IT staff will maintain a database or equivalent system to track wireless hardware allocation and user access. • ISSOs and local IT staff should provide additional training on the risks associated with wireless networks before they grant wireless privileges. • IT staff will periodically audit connections and connection attempts and report rogue hardware and security violations to the Area ISSO. 4. Inappropriate Use The following list describes inappropriate use of wireless networks. • Unauthenticated or unencrypted wireless communications are not permitted on the IHS network. • The use of wireless keyboards is not allowed on IHS networks or equipment. • Wireless communications must not be used to bypass IHS security controls such as Websense and firewalls. • Users are required to comply with the General User Security Handbook SOP06- 11a, which prohibits the insecure storage or transmission of sensitive data. Users may not send, store, or process patient information without appropriate security safeguards, as per HIPAA privacy and security requirements. • Wireless devices are not to be used within an environment where they may disrupt other systems (for example, telephone, healthcare equipment, and radio/microwave transmitters). • Per-session dynamic RC4 keys, including but not limited to dynamic wired equivalent privacy (WEP), temporal key integrity protocol (TKIP), and WPA, must not be used to secure WLAN communications. • The use of static or pre-shared keys is not permitted. • Wireless connections must not be used to administer the WLAN or LAN. • Ad-hoc connections between endpoint wireless devices without a centralized infrastructure are prohibited. 5. Ch ecklist

Use the following checklist to ensure that wireless devices and networks are secure. ☐ Wireless device is installed in a properly secured, adequately monitored location. ☐ Device IP address and supported IP address range is separate and unique from the wired IP ranges; that is, there is no possibility of any wired device using the WLAN IP addresses. ☐ Device configured with a static IP address. ☐ Device administration password changed from the default to a unique password conforming to the IHS password policy. ☐ Device SSID changed from the default to a unique, unpublished SSID. ☐ Device configured not to broadcast the SSID. ☐ Device configured to automatically disable its wireless network capability when physically plugged in through a port into the IHS enterprise wired network. ☐ If SNMP is active, SNMP community strings changed from manufacturer default to unique, unpublished strings. ☐ Device configured for WPA2 encryption. This is the minimum encryption requirement. ☐ Device WLAN isolated by a firewall with the principle of least privilege requirements (for example, specific IP addresses, protocols, ports). ☐ Inventory maintained and regularly updated with wireless devices, configurations, and authorized users. ☐ Device signal area and frequency are on non-overlapping channels and do not interfere with any other devices, wireless or otherwise (such as medical devices). ☐ After they are connected to the device, users are authenticated to an IHS central source, such as Active Directory. ☐ DNS entries conform to IHS naming conventions. ☐ Personnel are designated to periodically scan WLANs or monitor a wireless intrusion detection system (IDS). ☐ Wireless users have been trained on the risks associated with using a wireless device. Type: Windows Availability: Freeware, http://www.visiwave.com/ Description: VisiWave Site Survey is a complete 802.11a/b/g/n site surveying solution. It collects survey data using a standard wireless adapter while walking around the survey area clicking on a floor plan image, using a GPS receiver to track your location, or using a customized navigation device.

Name: AirSnort Wireless Sniffer
Type: UNIX Availability: Freeware, http://airsnort.shmoo.com/

Description: AirSnort is a freeware wireless LAN sniffer tool that recovers encryption keys. AirSnort operates by passively monitoring transmissions, computing the encryption key when enough packets have been gathered.

Name: Kismet Wireless Sniffer
Type: UNIX Availability: Freeware, http://www.kismetwireless.net/ Description: Kismet is an 802.11b wireless network sniffer. It is capable of sniffing using almost any wireless card supported in Linux.

Name: Netstumbler Wireless Sniffer
Type: Windows Availability: Freeware, http://www.netstumbler.com Description: Netstumbler is an 802.11b tool that listens for available networks and records data about that access point. A version is available for the Pocket PC.

Name: WEPCrack WEP encryption cracker
Type: UNIX Availability: Freeware, http://sourceforge.net/projects/wepcrack/ Description: WEPCrack is a tool that cracks 802.11 WEP encryption keys using the latest discovered weakness of RC4 key scheduling.
