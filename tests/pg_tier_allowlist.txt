# PG pytest tier allowlist (kph) — run by tools/testing/pg_pytest_tier.py under
# ICDEV_PYTEST_PG=1 against a LIVE PostgreSQL service so PG-native `%s` /
# portability bugs fail loudly (SQLite masks them via translate_sql).
#
# ONLY list tests that genuinely exercise runtime DB code on the AMBIENT backend
# — i.e. they do NOT self-force sqlite (no monkeypatch.setenv ICDEV_STORAGE_BACKEND
# or ICDEV_DB_PATH redirect in their fixtures) and do NOT roll their own raw
# sqlite3 connection. The deeper PG/RLS assertions (audit persistence, cross-tenant
# isolation) come from the verify_* scripts the runner also executes, because those
# purpose-built checks force real PG whereas the equivalent unit tests self-force
# sqlite.
#
# One path per line; blank lines and `#` comments are ignored. Grow this as new
# PG-safe, DB-exercising tests land (the coherence check_test_db_isolation gate
# keeps new tests honest about connection style).

# swp-audit-01: the deployed audit_trail event_type CHECK must admit exactly
# VALID_EVENT_TYPES. On SQLite that assertion skips (no audit_trail in the
# per-test DB), so this tier is the only place the REAL constraint is compared
# against the constant — which is how the 221-vs-189 drift went unnoticed.
tests/test_audit_event_type_parity.py
# AuditStore / `icdev audit tail`. Qualifies on the rule above: the SQLite cases
# inject their own connection_factory rather than forcing the ambient backend,
# and the two test_pg_* cases read the AMBIENT connection via get_connection.
# They exist specifically to catch a PG-only failure the SQLite cases cannot:
# audit_trail.created_at is `timestamp WITHOUT time zone` on PG while the
# --follow cursor is a tz-AWARE ISO string, so the comparison that drives
# --follow is only ever exercised for real here.
tests/test_audit_tail_cli.py
# kax-conflict-01: the pr_watcher auto-rebase budget. `_count_audit_actions`
# carries a PG-only `details::text` cast and builds a multi-placeholder IN
# clause; neither is exercised on SQLite, so a broken query there would return 0
# silently — i.e. an unlimited rebase budget — while the SQLite cases stayed
# green. The PG case seeds rows inside a transaction and ROLLS BACK, so the
# append-only audit_trail accumulates nothing.
tests/ci/test_pr_watcher_rebase.py
# sbx-fld-04: the Component License upsert into sbom_components. That table has
# never been written by any runtime path before, and _persist_components reports a
# failure as a stderr warning rather than raising — so a PG-only breakage in its
# `ON CONFLICT … DO UPDATE SET … = EXCLUDED.…` would show up as "0 rows recorded"
# while the SQLite suite stayed green. The file has no sqlite-forcing fixture; it
# reads the AMBIENT connection via get_connection and deletes its probe row in a
# fixture teardown, so nothing accumulates.
tests/pg_tier/test_sbom_component_license_pg.py
# sbx-cov-02: the sbom_dependencies.relationship_type CHECK. Its PostgreSQL
# branch is a plain ADD CONSTRAINT guarded by an information_schema lookup,
# because PG has no ADD CONSTRAINT IF NOT EXISTS; the SQLite branch takes a
# completely different path (table rebuild — SQLite cannot add a CHECK in
# place), so the SQLite cases exercise none of the shipping PG code. The PG
# case builds a throwaway schema and DROPs it, touching no live table.
tests/test_sbom_dependency_graph.py
# exa-policy-05: the SaaS MCP per-tool authorization audit write. audit_platform
# is a PostgreSQL-side table and is absent from the SQLite icdev.db, so the
# schema-parity test skips in the normal tier and only ever executes here.
# _write_authz_audit swallows its own exceptions on purpose (an audit outage
# must not 500 a call the policy allowed), which means a column that does not
# exist in the live schema would make every monitor-mode row vanish silently and
# monitor mode would report a clean board while recording nothing. This tier is
# the only place that failure mode is visible.
tests/test_exa_policy_05_saas_mcp_authz.py

# ctx-perf-05: whether the planner CHOOSES the composite RLS index is a
# cost-based decision — no SQLite assertion and no mock can stand in for it, and
# on the ~200 rows a dev cortex_audit holds PostgreSQL correctly ignores every
# index, so the assertion would be vacuous anywhere but here. Seeds a 200k-row
# schema of its own, EXPLAINs the real metrics._scan shape before and after
# creating the index, and drops the schema in finally; never touches public.
# Deviates from the ambient-connection rule above on purpose: it uses raw
# psycopg2 because it needs DDL plus EXPLAIN on its own schema and must see the
# RLS predicate as literal SQL it controls, that predicate being the subject.
tests/pg_tier/test_cortex_rls_index_plan.py
